## 🎭 复读模式

复读目标是全局唯一的：同一实例同时只能「变成」一个目标，但复读只发生在发起命令的群中。`/copy stop` 可在任意群停止当前复读。发起复读的群被 `/init disable`、机器人离群或被撤管理员时，复读随之停止并立即落盘，头像在后台静默复原为默认头像，不在群里发消息。

| 命令 | 行为 |
| :---: | :--- |
| `/copy` | 原样复读 |
| `/copy reverse` | 按字素簇反转文字与图注 |
| `/copy nya` | 在文字与图注末尾追加「喵~」 |
| `/icon steal` | 只复制头像 |
| `/icon reset` | 把头像换回机器人自己的默认那张 |
| `/copy stop` | 停止全局复读状态，并顺带复原头像 |

### 发送与变换机制

`/copy` 系与随机复读共用相同的发送规则：
- **文本与图注**：一律按字符串处理，带链接或 @ 的文字照样变换。纯文字重新发送，链接与 @username 由 Telegram 重新识别，原消息的链接预览设置照搬。
- **格式实体限制**：粗体、隐藏链接、剧透、自定义表情等格式不保留，剧透文字会以明文发出。
- **富媒体处理**：图片、视频、文件、贴纸等由 Telegram 在服务端原样复制，有图注时换成处理后的文字，本机不下载任何文件。付费媒体不能复制，只发文字。
- **纯非文本消息**：投票、骰子、位置、联系人这类没有文字也没有文件的消息原样复制。
- **长度越界**：变换后超过 Telegram 正文或图注长度上限时整条不发。

### 目标与参数指定

目标可通过「回复 TA 的消息」或 `@username` 指定：
- **模式语法**：模式写在目标前，例如 `/copy reverse @username`、`/copy nya @username`；只换头像用 `/icon steal @username`。`/copy stop` 与 `/icon reset` 不接受额外参数。
- **用户名观察依赖**：按用户名查找依赖机器人此前观察到该账号；改名、移除用户名或用户名换绑会立即使旧别名失效。对 `/block … enable`、`/block … disable` 这类破坏性操作，优先回复目标消息或直接给用户 ID，不要依赖历史用户名。
- **匿名管理员**：以当前群身份发言时，复读目标就是当前群，可取得群头像并复读这层「皮套」；`/block` 会拒绝把当前群身份当作成员目标。
- **冷却限制**：`/copy`、`/copy reverse`、`/copy nya` 与 `/icon steal`、`/icon reset` 共用 **5 分钟全局冷却**。仅 `SUPER_ADMIN_USER_ID` 本人豁免，白名单身份仍受冷却限制。`/copy stop` 不占冷却。

## 🌐 按群翻译

翻译处理文字与图注，独立于全局 copy 目标、5 分钟冷却和头像操作。先由拥有 `isCanControllTranslatePermission` 的身份执行 `/translate enable`（默认关闭），并提供有效的 `g-auth.json`。翻译目标是另一个机器人时，需要在 @BotFather 为本机器人开启 Bot-to-Bot Communication Mode，才能接收对方的普通消息；收到后仍受[其他 Bot 消息入口限流](04-invariants.md)约束（见 [01 环境搭建](01-getting-started.md)）。译文在后台按群依次发出，不拖慢其它消息的处理；同一群积压的待翻译消息过多时，新消息不再翻译，直到积压减少。

| 命令 | 行为 |
| :--- | :--- |
| `/translate ja` | 回复目标消息，把后续文字翻成日语 |
| `/translate cn @username` | 按已观察到的用户名指定目标，翻成简体中文 |
| `/translate en` | 回复目标消息，翻成美式英语 |
| `/translate uk` | 回复目标消息，翻成乌克兰语 |
| `/translate ru` | 回复目标消息，翻成俄语 |
| `/translate list` | 以 JSON 代码块列出支持正则判断的语言 |
| `/translate stop` | 不带回复或目标时停止本群全部会话，保留功能开关 |
| `/translate stop @username` 或 `/translate stop 123456789` | 停止指定目标；也可回复目标消息，频道身份支持负数 ID |
| `/translate disable` | 删除本群全部会话并关闭翻译功能；需要翻译管理权限 |

### 会话容量与互斥规则

- **会话配额**：群成员可以开始、停止会话；每群最多 5 个不同身份，每个身份独立选择方向，最多 25 群。新增超出容量时拒绝，不淘汰已有会话；同一身份换方向前先停止它。
- **冲突处理**：回复目标与参数冲突时拒绝，不会转为停止全群。
- **与复读互斥**：`/copy stop` 不停止翻译；同一身份同时命中 copy 和翻译时**只做翻译**（不复读、不复制媒体，也不同步表情回应）；其他 copy 目标照常工作。

`/translate list` 的内容如下，发送时使用 Telegram `pre` 实体并标记 `json`，群内 30 秒后删除：

```json
{
  "ja": "日语",
  "cn": "简体中文",
  "en": "美式英语",
  "uk": "乌克兰语",
  "ru": "俄语"
}
```

### 语种正则与发送规则

- **预过滤规则**：文字与图注一律按字符串翻译，带链接、@ 或格式实体的文字同样翻译。正则识别为目标文字，或只有数字、标点、表情的文字时，不调用翻译 API，整条不发送。
  - **日语**：需要假名。
  - **简体中文**：排除 Unicode Unihan 中具有简化变体的繁体字。
  - **英语**：接受 ASCII 字母。美式英语使用支持 `en-US` 的 [Google Translation LLM](https://docs.cloud.google.com/translate/docs/languages#translation-llm)。
  - **乌克兰语**：接受本语种字母与撇号，排除俄语的 `ёъыэ`。
  - **俄语**：接受 `Ё/ё`，排除乌克兰语的 `єіїґ`。
  - *注*：共用汉字、无重音拉丁字母和共用西里尔字母短句仍可能有语种歧义，正则不做语义级语言识别。
- **发送形式**：翻译只发译文，不发原文，也不复制媒体；翻译 API 失败或译文与原文逐字相同时整条不发送。
  - 译文按字符串发出，格式不保留，文字消息照搬原消息的链接预览设置。
  - 带图注的图片、视频、音频、文件与付费媒体只把图注译文作为文字发出，媒体本身不复制。
  - 没有文字的图片、贴纸、文件等以及投票、位置这类消息不发送，也不回落到同目标的 copy。
  - 译文超过正文长度上限时不发。输出保留话题，拒绝可渲染命令；命令提示 30 秒后删除。
- **持久化状态**：会话保存在 SQLite `chat_states` 本群行的 `translate` 数组中。停止单人只取消该目标；新增、停止其他人不取消当前目标的在途翻译。禁用和群 teardown 删除全群会话，异步结果在发送前重新核对该目标的会话对象。`/bot_status` 显示本群正在使用翻译的 `人数/5`。

| `/h_image add` | `isCanAddHImage` | 回复一条带图的消息，把这张图（相册则连同已见过的同组其余几张）收进随机图库；结果汇总 30 秒后删除 |

| `/permission …` | `SUPER_ADMIN_USER_ID` | 修改已有白名单用户/频道的一项权限；`all` 可全部打开 |
| `/white … enable\|disable` | 新增：`isCanWhiteOther`<br>删除：`SUPER_ADMIN_USER_ID` | 支持回复、`@username`、用户 id 与频道 id；委托新增只授予默认权限，修改已有权限由超级管理员执行 |
| `/bot_status` | `isCanViewBotStatus` | 查看本机进程指标、全局模型能力、Telegram 429 出站队列、AI 上下文容量、正在生效的 gag 数量、本群翻译人数（最多 5 人）、本天才在本群已拥有的权限（JSON 块）和本群各项功能开关的真假（JSON 块，逐项列出，没开的给 false） |
| `/init enable\|disable` | `SUPER_ADMIN_USER_ID` | 开关本群的业务处理总入口 |
| `/batch_kick <Nm\|Nh\|Nd>` | `SUPER_ADMIN_USER_ID` | 在超级群中踢出滚动 24 小时内指定时间窗加入且仍在群内的成员；只踢不拉黑 |
| `/send <群组 ID>`<br>`/send finish` | `SUPER_ADMIN_USER_ID`（仅私聊） | 在机器人私聊中开始或结束向目标群的中转；中转期间把 TTS 请求整条作为代码块发送，可让机器人以语音气泡说出来 |

> [!IMPORTANT]
> **权限列的读法**：
> - 写 `isCanXxx` 的行按权限键授权，而 `SUPER_ADMIN_USER_ID` 这个身份本身恒持有**全部**权限键，因此那些行他一律可用，无需写入 SQLite 白名单表。
> - 写 `SUPER_ADMIN_USER_ID` 的行则是**只认身份、无法通过白名单授权出去**的硬性边界。

### 参数与目标匹配准则

- **话题消息处理**：论坛话题自动填入的创建消息按“未显式回复”处理，命令仍可按参数指定目标；显式回复该创建消息本身也按同一规则处理。关联频道讨论组的评论回复正常保留。
- **策略预热**：所有依赖目标黑白名单的身份修改与成员操作须先完成策略预热，失败只回复短时提示，不继续执行。
- **统一入口菜单**：在聊天框菜单中，`/copy`、`/qa`、`/mood`、`/icon` 作为统一入口，描述中列出各自参数。缺少或使用非法子命令时只回复用法。
  - `/qa set`、`/mood query`、`/mood switch` 不接受额外参数。
  - `/qa query` 省略问题时列出全部，`/qa remove` 必须带问题；查询和删除均保留问题内部的空格与换行。
- **子命令词大小写**：`/copy stop|reverse|nya`、`/icon steal|reset`、`/qa set|remove|query`、`/translate <方向>|stop`、`/mood query|switch`、`/h_image add` 的子命令词一律不区分大小写，口径与 `/block`、`/white`、`/init` 一致。跟在子命令词后面的目标参数与问答文本保持原样大小写，不跟着折叠。
- **按钮回调校验**：入群验证、`/wed` 与 `/qa query` 看板翻页的 `callback_data` 里那串数字按规范十进制严格解析（不带正号、前导零、空白、小数点与指数）。本机器人生成的按钮只可能是规范十进制，其余写法当场按「按钮失效」应答。

### 行为细节

#### 1. 人设与通知语气
- 人设是进程级部署输入，没有按群配置的命令。
- AI 人设使用项目根 `prompt/persona.md` 的正文，文件缺省时使用内置雌小鬼人设。命令提示、权限 help、按钮、自动通知、命令菜单与 inline 运势优先采用 `config/static/bot.json` 的显式 `atmosphere`（`mesugaki` 雌小鬼版，`normal` 普通版）；风格未配置时，自定义人设使用普通版，内置人设使用雌小鬼版。
- 两者都在启动时确定，修改后重启生效；AI 开关不影响选择。
- 启动只注册所有群聊作用域的菜单并清除默认作用域，私聊不显示菜单；私聊命令只响应超级管理员的 `/send`。

#### 2. `/bot_status` 指标采集
- **模型能力**：只列配置已就绪的能力，按「能力名：模型名」展示；模型名去掉最后一个 `/` 前的命名空间，xAI 语音合成展示音色。可选的图片生成、语音合成和独立联网检索未配置时不列出；AI 对话或广告检测未就绪时不列对应能力。没有可列项时省略整段模型能力。
- **内存占用**：在收到命令时调用 `Bun.unsafe.memoryFootprint()`，展示整个 Bot 进程（含 Worker）的当前内存占用；Linux 使用 PSS，共享驻留页按进程分摊。百分比以容器内存约束为分母，无约束时使用本机物理内存总量；无法采样时显示「不可用」。
- **本群上下文容量**：滑动热记忆按 `VERBATIM_CONTEXT_MAX`（256 条）、冷记忆摘要按 `MAX_SUMMARY_ROUNDS`（7 轮）各算占用率，再按 7:3 加权求和，**只展示这一个百分比**。两个计数由 AI Worker 随记忆快照上报（周期 `AI_SNAPSHOT_INTERVAL_MS`，30 秒）带过来，并在 hydrate 完成后全量播种，主线程只持有只读镜像。待晋升摘要不计入冷区，镜像没有条目一律按 0 展示，读数最多滞后一个上报周期。

#### 3. 动作命令与 `/x`
- 姓名使用 `first_name last_name` 形式，有公开用户名的一方挂上主页链接；目标通过「回复 TA 的消息」或 `@username` 指定。
- 成功的动作结果与 `/permission help`、`/permission query` 一样长期保留；目标缺失、参数错误和 `/x` 用法提示在 30 秒后删除。

> [!TIP]
> **中文动作命令不需要预先登记**，任意 1~2 个中文字都能用。Telegram 命令名只收 ASCII，因此：
> - 这类命令既不出现在命令菜单里，也没有输入补全；菜单里只放了一条占位说明项 `/x`，点它会收到一条用法提示并终止链路。
> - `/咬人人` 这种三字及以上的写法不算动作命令，会按普通消息处理。
> - 全局滑动窗口限流：每 90 秒最多应答 450 次，不分群、不分用户合并计数，超额直接静默丢弃。

#### 4. 群问答：`/qa` 全生命周期
- **表单收集机制**：
  - `/qa set` 的表单靠**格式消息**收文本。开表单时按 `isCanControllQaPermission` 把关，随后只认开表单的身份（频道马甲与匿名管理员同样支持）。
  - 投递格式为行首的 `问题:` 或 `回答:`（半角/全角冒号皆可，`答案:` 同义），两条消息各带一样，或合在同一条发送。
  - 答案中的 ```` ```json ```` 代码块会以**字面围栏**存盘，直答时原样拆回发出，围栏本身计入 3840 字上限。
  - 认领后投递消息会被删除，不进流水线；表单就地改写回显当前状态。若两项合计超过 Telegram 单条 4096 字符，回答回显按剩余预算截断补省略号，登记进库的仍是完整原文。
- **并发与重置**：
  - 表单按群唯一，15 分钟超时自动收回。重发同一字段直接覆盖旧值；同一人再发 `/qa set` 会作废旧表单重开；其他人中途发 `/qa set` 会被当场拒绝。
  - `/init disable` 与 Bot 被移出群会把本群全部问答从库中删除；仅被撤销管理员权限则保留问答记录。
- **看板分页与直答**：
  - `/qa query` 看板固定 3 条一页，提供翻页按钮，点击就地改写消息。每次点击按 `callback_data` 页号从热表重新装页，答案截断到 256 字，**问题从不截断**。
  - **问答直答**：消息文本与登记问题一字不差时直接回答（剥除前导 `@机器人`），不经过 AI，不受随机插话约束。语义相近但文本不同的提问，由 AI 的 `group_qa_query` 与 `group_qa_answer` 工具在闲聊轮次中检索应答。

#### 5. 限制发言：`/gag`
- **容量与入口机制**：
  - 全局最多同时生效 5 个目标，同群可有多个目标但同一身份不能重复。
  - 普通用户在群内留下公开状态，并收到一条 `ephemeral_message_parameters.receiver_user_id` 限定、仅本人可见且带「发言」按钮的临时入口；频道身份则发送带按钮的公开状态。
  - 按钮预填 `gag:<目标 Telegram id>`。生成结果以隐藏文本链接携带 `<目标主页>#<会话群 id>`。消息落群后核对目标、群与真实发送身份，不匹配立即删除。
- **渲染与混淆算法**：
  - 逐个扩展字形抽样：75% 走填充分支（追加 3~6 个点，相邻点 1/3 概率插空格），25% 等概率替换为六种拟声字之一。
  - 同类操作最多连续作用于两个相邻字形。短文本有保底档位（2~3、4~7、8~31、32~64 字形分别至少操作 2、3、7、15 次）。
- **心跳与刷新机制**：
  - 每 **7 条** 群消息触发一次入口刷新。
  - 用户专属入口在首次激活及每次刷新后等待 **30 秒** 补发；若目标连续 **45 秒** 未发言，下次发言立即补发。
- **群不再受管时**：`/init disable` 或机器人被撤管理员时静默结束本群全部 gag 并删除提示；机器人已离群时直接释放会话与名额，不再尝试删除。

#### 6. 黑名单：`/block`
- **操作语法**：`/block <目标> enable` 拉黑，`/block <目标> disable` 解除。目标支持回复、`@username`、用户 ID（正整数）以及频道负数 ID（仅解封支持）。
- **生效范围**：拉黑后写入权威 SQLite 黑名单，并在所有已纳管群中秒踢/封禁。Bot 获得管理权限且群初始化时会自动补扫群内黑名单成员。
- **执行方式**：`enable` 确认名单落盘后，跨群封禁与战报在后台执行，战报稍后发出；同一目标的先后命令按到达顺序生效。`disable` 在命令内完成移出名单与逐群解封后回执。
- **销号清理**：若目标在群内封禁时连续 5 次返回 `PARTICIPANT_ID_INVALID`，判定为已销号，自动移出黑名单。

#### 7. 广告检测与防冲群
- **`/ad_detect`**：每条消息按发送者（`chatId:senderId`）归并成消息串，队列每秒取一批交 `agent.ad_detect` 模型判定。命中后按 `/block` 同权处置，并在群内播报封禁理由（30 秒自删）。纯代理链接（`vless://`、`vmess://`、`trojan://`、`ss://`）且无招募推销文案时不判广告。
- **`/flood_control`（防刷屏）**：同一个人在同超级群内 1 分钟发言达到 15 条，就地禁言 3 分钟并在群内播报（30 秒自删）。管理员、频道马甲不计数；豁免看 `isCanBypassFloodControl`。
- **`/antiraid`**：开启入群验证与防冲群私密模式。关闭时两条链路事件全部停止，发出的验证提醒立即撤回。广告检测、防刷屏、黑名单不受影响。
- **`/batch_kick`**：仅超级管理员可用，按入群日志在指定时间窗（如 `30m`、`2h`、`1d`，≤ 24 小时）内踢出新成员，只踢不封，白名单与黑名单身份均跳过。有记录时先回「已受理」（记录数与时长），踢人在后台进行，结束后发送战报；同群同一时间只跑一批，上一批未结束时回「仍在处理」，后台等待位已满时回忙碌提示；处理途中本群不再受管（`/init disable`、机器人离群或被撤管理员）时静默停止，不发战报。

#### 8. 私聊中转与语音代发：`/send`
- 开启前探测目标群是否可达，中转期间超级管理员在私聊发送的每条消息原样转发至目标群。
- **语音代发**：将整条消息以 JSON 代码块发送：
  ```json
  { "type": "tts", "tone": "需要的语气", "text": "需要转换的文本" }
  ```
  - 台词上限 256、语气上限 64（UTF-16 码元）。
  - 合成由后台异步执行，需要 `config/dynamic/agent.json` 中配置 `agent.tts`。
  - 额度共享 `agent.tts.daily_reserve_quota`（缺省 25 次，与 AI 闲聊额度隔离）。

> [!TIP]
> **`/luck_challenge` 不是斜杠命令**：在任意聊天输入 `@机器人用户名 [所求事项]` 即可使用 Inline Mode 抽取运势。需在 BotFather 中开启 Inline Mode。全局滑动窗口限流：每 90 秒最多应答 300 次。

## 💍 群友老婆：`/wed`

群已执行 `/init enable` 后，群成员在群内发送 `/wed`（无需参数）。机器人回复命令并发送所选用户的头像，图注为「发起人，你的群友老婆是 群友!」，下方提供交互按钮：

| 按钮 | 行为 |
| :--- | :--- |
| **移除** | 删除这张结果并释放会话 |
| **娶老婆!** | 确认当前结果，中间按钮变为「已确认♡」；仍可继续更换 |
| **换一只** | 在同一条消息中更换头像和图注，排除发起人及当前目标，恢复确认按钮 |

### 核心运作机制

- **操作独占**：结果仅发起人本人可操作。更换前的旧按钮点击不会作用于新目标。再次发送 `/wed` 会重新抽取并删除旧结果，每位用户每群只保留一张结果。
- **候选池构建**：
  - 每群独立、长期复用的 **`Set<number>`，上限 15 万人**。
  - 仅记录在已初始化群中以**个人身份**实际发言的用户（不收录频道、匿名管理、服务消息）。
  - 满额后暂停新增；离群更新会即时从集合删除对应 ID。
  - 每天配置时区时间 00:00，Bun cron 触发主线程按每秒最多 5 个 ID 复核群成员（需管理员权限调 `getChatMember`）；非管理员群依赖退群服务消息清理。
- **头像读取与缓存**：
  - 抽中候选后调用 `getChat` 获取资料，从 `getUserProfilePhotos` 前 100 张中按 `big_file_unique_id` 匹配尺寸。
  - 匹配成功后复用 `PhotoSize.file_id` 直接转发，本机不下载、不上传。未匹配时下载当前 ChatPhoto 发送。
- **并发与限流**：
  - 命令与按钮共享主线程执行器：全局最多同时并发 **32 项**，队列上限 **512 项**（FIFO），满额提示稍后再试。
  - 成员 ID 列表以 JSON 数组保存在 `memory/wed/<chatId>.json`，累积 256 条变更或 30 秒后由 DiskIO 批量落盘。
  - 会话每群最多 512 张，满额拒绝新群（最多 25 群）。结果消息不挂 30 秒删除，由按钮交互或群 teardown 销毁。

## 🔎 查资料：`/info`

群已执行 `/init enable` 后，任何人都能用 `/info` 查一个身份的公开资料：回复 TA 的消息发 `/info`，或写 `/info @username`、`/info <用户 id>`、`/info <频道或群 id>`。目标可以是用户、频道、其他 bot，也可以是机器人自己。

- **返回内容**：名称（用户为 `first_name last_name`，频道/群为标题）、用户名（无则标明）、ID（支持点击复制）。有头像时随附头像，无头像时注明。
- **数据来源**：每次现查。用户读群内资料，频道/群读会话资料，机器人读自身资料；头像复用 `/wed` 同套抓取逻辑（用户头像复用 file_id，频道头像下载上传，t.me 兜底）。
- **留存与限制**：回执及错误提示均在 **30 秒后删除**。查询交给共享的延迟命令执行器，出队后单次查询预算为 30 秒；队列满额回「稍后再试」。私聊发 `/info` 不响应。

## 🖼️ 随机图片：`/h_image`

**图库配置**：`config/dynamic/assets.json` 的 `onlyPath.random_h_image_dir`（默认 `./h_image`，相对运行时数据根解析）。

群已执行 `/init enable` 后，发送 `/h_image`（不带参数）即可从图库中均匀随机抽选一张发送至本群。

- **格式与过滤**：只识别图库根目录下的 `jpg`、`jpeg`、`png`、`webp`（忽略隐藏文件、子目录与符号链接）。文件超过 10 MB 自动跳过并重抽。放图、删图无需重启。
- **剧透遮罩**：结果图片固定携带 Telegram 剧透遮罩（`has_spoiler`），以马赛克/模糊图发出，点击后展开。
- **留存规则**：图片**长期保留**；非法参数用法提示、目录空/不存在/超大图等错误提示在 **30 秒后删除**。
- **并发与限流**：
  - 延迟命令执行器全局并发 **2 项**，排队位 **16 项**。
  - 滑动窗口限流：与 `/h_image add` 合计每秒最多受理 **5 次**，超额静默丢弃。

### 收图：`/h_image add`

持有 `isCanAddHImage` 权限的身份回复带图消息并发送 `/h_image add`，即可将图片收录进随机图库。

- **收录范围**：被回复消息的原图（最大尺寸），或文件形式的 `jpg`/`png`/`webp`。若属于相册，机器人见过的同组其余图片一并收录（单相册上限 10 张，内存缓存最近 256 个相册）。
- **内容寻址与去重**：
  - 文件名严格采用**图片二进制内容的 SHA-256** 加文件头扩展名（如 `<hash>.jpg`）。
  - 去重发生在下载后计算哈希时：若图库已有相同哈希文件，提示已存在，不重复写盘。
- **尺寸合规限制**：Telegram `sendPhoto` 限制宽高和 ≤ 10000、宽高比 ≤ 20。收图时会预检尺寸，超限图片直接拒绝收录。
- **落盘安全**：先写为点号开头的临时文件，写完后在同目录原子 `rename`，避免抽图读取半写入文件。
- **回执与超时**：执行上限 120 秒；完成后发送汇总报告（收录数、原图库数、跳过数、超限数），提示在 30 秒后删除。

## ⏰ 定时发送：`cron.json`

定时任务由部署方配置 `config/dynamic/cron.json`，支持热重载，无群内编辑命令。

- **投递范围**：可向指定会话、所有已启用且有发送权限的群，或排除部分群后的集合发送文字、图片、文件与语音。
- **图片与遮罩**：固定图片支持 1–10 项 `url` 或本地 `path`（2–10 张自动组装为相册，首图带说明）；随机模式每次一张。`is_blurred` 开关控制图片的剧透遮罩。
- **语音广播（`send_voice`）**：将 `content` 按可选 `tone` 合成语音气泡发出。必须在 `agent.json` 中配置 `agent.tts`，否则启动拒绝或热重载拒绝。
- **搜索汇总（`send_web_digest`）**：按简短 `topic` 检索主题，按 `instructions` 的任务规则整理成 MarkdownV2 摘要，最多 15 条，条目正文支持换行。优先使用 `agent.web_search`，未配置时使用 `text` 内建检索；模型未调用搜索时直接发送带“注意，以下可能为模型侧缓存内容，请仔细甄别”的正文。
- **生命周期**：定时消息长期保留，在论坛群落到 General 话题。一次性任务与随机时刻仅在内存登记，停机期间错过的任务不补发。详细配置规范见 [部署配置说明](../../config_example/README/zh.md#cronjson)。
