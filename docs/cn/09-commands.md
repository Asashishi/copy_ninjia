## 🎭 复读模式

复读目标在整个机器人实例中是**全局唯一**的：同一个实例在同一时刻只能“变身”为一个指定目标，且复读行为仅发生在发起该命令的群聊中。
使用 `/copy stop` 可以在任何群组立即终止当前的全局复读状态。当发起复读的群被 `/init disable` 禁用、机器人被移出群聊或被撤销管理员权限时，复读状态会自动停止并立即落盘，机器人头像在后台静默重置为默认头像，不会在群内发送提示。

| 命令 | 行为说明 |
| :---: | :--- |
| `/copy` | 原样复读目标的后续发言 |
| `/copy reverse` | 按 Unicode 字素簇倒序反转文字与图注后发出 |
| `/copy nya` | 在文字与图注末尾自动追加「喵~」后发出 |
| `/icon steal` | 仅复制目标的头像为机器人头像，不开启文字复读 |
| `/icon reset` | 将机器人头像恢复为默认配置的初始头像 |
| `/copy stop` | 停止当前的全局复读，并同步将机器人头像重置为默认头像 |

### 发送与变换机制

`/copy` 命令族与系统的随机复读功能共享相同的消息处理规则：
- **文本与图注**：统一作为普通字符串处理，包含链接或 `@username` 的内容同样执行变换。纯文字消息会重新发出，链接与 `@username` 依然由 Telegram 客户端重新识别，并继承原消息的链接预览开关设置。
- **样式实体丢弃**：粗体、下划线、隐藏链接、剧透遮罩、自定义表情等富文本样式不会保留；原消息中带有剧透遮罩的文字会以明文形式直接发出。
- **富媒体处理**：图片、视频、文件、贴纸等媒体由 Telegram 服务端直接复制转发；若带有图注（Caption），则将图注替换为变换后的文本，机器人本地不下载任何文件。付费媒体（Paid Media）无法直接复制，仅转发文字图注。
- **纯非文本消息**：投票、骰子、地理位置、名片联系人等既没有文字也没有媒体文件的特殊消息，将原样转发。
- **命令防循环拦截**：变换前或变换后的文本若命中 Telegram 可渲染的斜杠命令，整条消息不予发送。
- **超长保护**：文本变换后若超出 Telegram 消息正文或图注的字数上限，整条消息不予发送。

### 目标与参数指定

可以通过“回复某人的消息”或显式输入 `@username` 来指定复读目标：
- **参数语法**：模式参数位于目标之前，例如 `/copy reverse @username`、`/copy nya @username`；仅偷取头像使用 `/icon steal @username`。`/copy stop` 与 `/icon reset` 不接受额外参数。
- **用户名缓存依赖**：通过 `@username` 查找目标的前提是机器人此前已经在群内观察到该用户的发言并建立了本地缓存。如果目标用户修改了用户名、移除了用户名或换绑了新号，旧用户名缓存会立即失效。对于 `/block … enable` 等不可逆管理操作，建议优先回复目标消息或直接指定数字 ID。
- **匿名管理员支持**：群管理开启匿名管理员身份发言时，其消息来源即代表当前群组本身。复读该消息会以群组为目标，取得群头像并复读该“马甲”；但 `/block` 命令会直接拒绝封禁当前群身份。
- **全局冷却限制**：`/copy`、`/copy reverse`、`/copy nya` 与 `/icon steal`、`/icon reset` 共享全局冷却时间（`COPY_COOLDOWN_MS`）。仅配置的超级管理员（`SUPER_ADMIN_USER_ID`）本人享有冷却豁免，普通白名单用户仍需遵守冷却间隔。`/copy stop` 不受冷却时间限制。

## 🌐 按群翻译

按群翻译功能独立于全局复读状态、头像与复读冷却。使用前需先由具备 `isCanControllTranslatePermission` 权限的管理人员执行 `/translate enable` 开启（默认关闭），且部署方已配置有效的 `g-auth.json`。
若翻译目标是另一个机器人，需在 @BotFather 开启本机器人的 Bot-to-Bot Communication Mode 才能接收其发言，且依然受[其他 Bot 消息入口限流](04-invariants.md)保护（参考 [01 环境搭建](01-getting-started.md)）。
翻译任务由后台按群串行排队发出，不会阻塞常规消息的吞吐；当单群积压待翻译消息达到 `TRANSLATE_CHAT_BACKLOG_MAX` 上限时，新消息将被丢弃不再翻译，直至队列排空。

| 命令 | 行为说明 |
| :--- | :--- |
| `/translate ja` | 回复目标消息，将其后续发言实时翻译为日语 |
| `/translate cn @username` | 指定已观察到的用户名，将其后续发言翻译为简体中文 |
| `/translate en` | 回复目标消息，将其后续发言翻译为美式英语 |
| `/translate uk` | 回复目标消息，将其后续发言翻译为乌克兰语 |
| `/translate ru` | 回复目标消息，将其后续发言翻译为俄语 |
| `/translate list` | 以 JSON 代码块展示当前支持正则快速识别的语言列表 |
| `/translate stop` | 若未带参数或回复，停止本群内的所有翻译会话（保留功能开启状态） |
| `/translate stop @username` 或 `/translate stop 123456789` | 停止指定目标的翻译会话；也可回复目标消息执行，频道身份支持负数 ID |
| `/translate disable` | 清空本群所有翻译会话并关闭翻译功能（需管理权限） |

### 会话容量与互斥规则

- **会话配额管理**：普通群成员均可为目标开启或停止翻译会话。单个群内同时处于翻译状态的不同用户身份上限为 `TRANSLATE_CHAT_USER_LIMIT`，每个身份可独立选择翻译目标语言；全实例托管群总数受 `STATE_MANAGED_CHAT_LIMIT` 约束。超出容量上限时新增会话将被拒绝，不会自动挤占或逐出已有会话；修改翻译语言前需先停止当前会话。
- **参数冲突校验**：若同时回复了一条消息又在命令中附带了不一致的目标参数，命令将被直接拒绝，不会误触发停止全群。
- **与复读互斥**：`/copy stop` 不会影响正在运行的翻译会话；当同一个用户同时被设定为复读目标和翻译目标时，系统**优先执行翻译**（不复读原文、不复制媒体、不追加表情）；其他用户的复读不受影响。

执行 `/translate list` 返回的支持语言字典如下（以 Telegram `pre` 实体附带 `json` 语法高亮发送，作为命令回执将在 30 秒后自动删除）：

```json
{
  "ja": "日语",
  "cn": "简体中文",
  "en": "美式英语",
  "uk": "乌克兰语",
  "ru": "俄语"
}
```

### 语种正则与发送规则

- **前置正则过滤**：文本与图注均按纯字符串处理。如果消息经正则判断已经属于目标语种，或者消息仅由纯数字、标点符号、Emoji 表情构成，系统不会调用外部翻译 API，整条消息直接忽略不发：
  - **日语**：必须包含日文假名（平假名/片假名）。
  - **简体中文**：排除在 Unicode Unihan 中具备简化字对照的繁体汉字。
  - **英语**：接受 ASCII 字母。美式英语接口调用支持 `en-US` 的 [Google Translation LLM](https://docs.cloud.google.com/translate/docs/languages#translation-llm)。
  - **乌克兰语**：接受乌克兰语特有字母与撇号，排除俄语的 `ёъыэ`。
  - **俄语**：接受 `Ё/ё`，排除乌克兰语特有的 `єіїґ`。
  - *说明*：中日共用汉字、无重音拉丁字母或短句西里尔字母可能存在语种歧义，前置正则不做复杂的深度语义识别。
- **译文发出形式**：翻译仅发送翻译后的译文，不重复发送原文，也不转发媒体；若翻译 API 调用失败，或返回的译文与原文完全逐字一致，整条消息不发。
  - 译文以纯文本发出，富文本格式不保留；若原消息包含链接，会保留原消息的链接预览设置。
  - 带有图注的图片、视频、音频、文件或付费媒体，仅提取图注翻译后作为文本发出，媒体文件本身不复制。
  - 纯无文字的图片、贴纸、文件、投票、定位等消息不予翻译，也不会回落为复读。
  - 译文长度超出 Telegram 消息上限时不发；保留原始触发话题（Thread），拦截可渲染的斜杠命令；各类命令提示消息均在 30 秒后自动删除。
- **持久化与恢复**：翻译会话持久化在 SQLite 的 `chat_states` 表对应群的 `translate` JSONB 字段中。停止某个用户的翻译仅撤销该用户，不会打断其他人的在途翻译任务。执行 `/translate disable` 或机器人离群会彻底清空本群会话。使用 `/bot_status` 可以实时查看本群当前的翻译人数与上限。

### 参数与目标匹配准则

- **论坛话题消息**：Telegram 论坛话题（Topics）创建时系统自动生成的服务消息，在被命令回复时按“未显式回复具体消息”处理，命令仍可通过 `@username` 或 ID 指定目标。关联频道的讨论组自动转发消息被评论时则正常作为回复目标。
- **权限预热保障**：所有涉及查询或修改黑白名单的命令，在执行前必须完成内存中的权限策略预热；若预热失败，系统仅回复一条短时提示并终止执行，防止在无保护状态下放行操作。
- **命令菜单交互**：带有子命令的复杂命令（如 `/copy`、`/qa`、`/mood`、`/icon`）在客户端命令菜单中作为独立条目登记，并在描述中列出常用语法。若输入缺失或传入未定义的子命令，机器人仅回复该命令的用法说明。
  - `/qa set`、`/mood query`、`/mood switch` 不接受额外参数。
  - `/qa query` 省略问题时展示全部列表，`/qa remove` 必须提供具体的问题文本；查询与删除均严格保留问题文本内部的空格与换行符。
- **提示消息 30 秒自动删除**：在群组内执行命令时，因校验失败、权限不足、用法提示或操作成功产生的所有非功能性回执，统一在发送成功 30 秒后（`COMMAND_MESSAGE_AUTO_DELETE_MS`）自动删除，保持群聊整洁。
  - **允许长期保留的例外**：`/permission help`、`/permission query` 的权限看板、`/qa query` 的问答看板、问答直答匹配出的答案文本、中文动作命令的成功执行结果、`/h_image` 抽出的图片、`cron.json` 发送的定时消息，以及复读、翻译、AI 回复等会话产物。
  - **状态机拥有的消息**：入群验证按钮、`/qa set` 录入表单、`/wed` 抽取结果及操作按钮、gag 限制发言公告等，不挂固定延迟自删，统一由用户点击按钮、业务状态机流转或群组被注销时销毁。
- **子命令大小写不敏感**：`/copy stop|reverse|nya`、`/icon steal|reset`、`/qa set|remove|query`、`/translate <语言>|stop`、`/mood query|switch`、`/h_image add` 等子命令关键词均不区分大小写，与 `/block`、`/white`、`/init` 保持一致。但紧跟在子命令后的目标用户名、ID 或问答正文保持原始大小写不变。
- **按钮回调安全性**：入群验证、`/wed` 交互以及 `/qa query` 翻页按钮的 `callback_data` 中的数字统一使用严格的正整数解析（拒绝正号、前导零、空格、小数点或指数形式）。非规范格式的回调将直接作为“按钮已失效”响应并忽略。

### 行为细节

#### 1. 人设与通知语气
- 人设提示词属于全实例级的部署配置，不支持在群内通过命令按群独立切换。
- AI 的人设内容默认读取项目根目录下的 `prompt/persona.md`；若文件不存在，则回落至内置的调侃雌小鬼人设。命令提示、权限说明、按钮文本、定时播报及 Inline 运势文案风格优先读取 `config/static/bot.json` 中的 `atmosphere` 配置（`mesugaki` 为调侃风，`normal` 为克制风）；若未显式配置，自定义人设默认采用克制风，内置人设采用调侃风。
- 风格在服务启动时固定初始化，修改后需重启进程生效。
- 启动时仅向 Telegram 注册群聊作用域的命令菜单，私聊窗口不显示菜单；私聊中仅响应超级管理员的 `/send` 中转命令。

#### 2. `/bot_status` 指标采集
- **各行文案随通知语气**：CPU、运行时长、内存占用、各模型能力名称与 Telegram 出站等行的标签取自当前通知语气的文案表（`packages/consts/atmosphere/{plain,teasing}/notices.ts`），克制风与调侃风各一套，数值与取舍规则相同。
- **模型能力列表**：仅列出当前配置已就绪的能力，以“能力名: 模型名”格式输出；模型名会自动去除前缀命名空间，xAI 语音合成会标注具体音色。未配置的图片生成、语音合成或独立联网检索不予展示；AI 对话或广告识别模块不可用时亦不展示该项。若无任何模型能力就绪，则省略该区块。
- **真实内存占用**：执行命令时调用 `Bun.unsafe.memoryFootprint()` 采样整个机器人进程（含所有 Worker 线程）的物理驻留内存；Linux 下采用 PSS 指标，共享只读库按比例分摊。百分比以 Docker/cgroup 内存限制为分母；若无容器限制，以宿主机物理内存为分母；若无法读取则展示“不可用”。
- **群上下文记忆饱和度**：根据近期的热记忆条数（以 `VERBATIM_CONTEXT_MAX` 为上限）与冷记忆摘要轮数（以 `MAX_SUMMARY_ROUNDS` 为上限）分别计算占比，并按照 `BOT_STATUS_HOT_MEMORY_WEIGHT` 与 `BOT_STATUS_COLD_MEMORY_WEIGHT` 权重加权计算出一个综合百分比展示。该统计数据由 AI Worker 随记忆快照定期上报，主线程仅读取快照缓存。
- **权限与功能状态**：以 JSON 代码块形式列出机器人在当前群组所持有的各项管理权限，并逐项输出本群内所有功能模块的开启状态（未开启的显示为 false）。

#### 3. 动作命令与 `/x`
- 成功触发动作命令时，回复文案采用 `发起人姓名 动作 目标姓名` 格式，拥有公开 Telegram 用户名的用户会自动附带主页超链接；目标可通过回复消息或 `@username` 指定。
- 动作成功执行的消息将长期保留；若目标缺失、参数错误或用户点击了菜单中的 `/x` 占位说明项，提示消息将在 30 秒后自动清理。

> [!TIP]
> **中文动作命令无需预先注册**，系统支持任意 1~2 个汉字的动作组合（如 `/咬`、`/抱`、`/摸摸`）。由于 Telegram 原生菜单仅支持 ASCII 字符：
> - 中文动作命令不会出现在官方输入候选菜单中；菜单中使用 `/x` 作为语法占位说明项，点击会收到使用示例。
> - 三个汉字及以上的输入（如 `/咬咬咬`）不会被识别为动作命令，将作为常规群聊消息处理。
> - 系统配备了全局滑动窗口限流：在 `CJK_ACTION_RATE_LIMIT_WINDOW_MS` 窗口内，全实例最多处理 `CJK_ACTION_RATE_LIMIT_MAX_CALLS_PER_WINDOW` 次动作命令，超出配额的请求将静默丢弃。

#### 4. 群问答：`/qa` 全生命周期
- **表单录入交互**：
  - 发送 `/qa set` 后，系统会为当前群开启问答录入表单会话（需具备 `isCanControllQaPermission` 权限）。表单开启后，仅接受该发起者本人发送的后续内容（支持频道身份与匿名管理员）。
  - 录入内容必须以行首的 `问题:` 或 `回答:` 为标识（全角/半角冒号均可，`答案:` 与 `回答:` 等价），可分两条消息发送，也可合并在一条消息中发送。
  - 回答内容中的 ```` ```json ```` 代码块会被原样字面存盘，后续触发直答时会原样发出；围栏本身计入字数限制 `CHAT_QA_ANSWER_MAX_CHARS`。
  - 问题整条、回答在代码块之外不能含有会显示成可点击命令的斜杠写法（如 `/start`、`/etc/hosts`）：与超长一样，该项不会被记录，表单保留并回执提示改写；代码块内的命令示例照常收下。
  - 成功被认领的录入消息会被立即删除，不会进入常规消息流水线；表单消息会就地编辑更新录入进度。两项内容齐备后即完成登记并存盘。
- **并发与有效期**：
  - 单个群同一时间只允许存在一个活跃的录入表单，闲置满 `QA_FORM_SESSION_TTL_MS` 后自动超时收回。重复发送同一个字段会直接覆盖之前的内容；发起者再次发送 `/qa set` 会废弃旧表单重开；其他人在表单开启期间发送 `/qa set` 会被直接拒绝。
  - 当群组被 `/init disable` 禁用或机器人被移出群聊时，该群名下的所有问答数据会被从数据库中彻底抹除；仅被撤销管理员权限时数据予以保留。
- **看板翻页与自动直答**：
  - 使用 `/qa query` 可以查看已录入的问答列表，按每页 `QA_QUERY_PAGE_MAX_ENTRIES` 条进行分页，提供翻页按钮就地改写消息；答案文本在看板中会按 `QA_QUERY_ANSWER_PREVIEW_MAX_CHARS` 截断预览，**问题文本则完整展示绝不截断**。
  - **精准直答**：当群成员发言与已录入的问题完全逐字一致时（会自动剥离消息开头的 `@机器人用户名`），机器人将直接回复预设的答案，不经过 AI 处理，不消耗模型配额，也不受静音模式限制。语义相似但文字不同的提问，则由 AI 在对话闲聊轮次中通过 `group_qa_query` 与 `group_qa_answer` 工具检索后回答。

#### 5. 限制发言：`/gag`
- **配额与入口机制**：
  - 全局同时受到发言限制的目标总数上限为 `GAG_SESSION_MAX`（包括正在建立与正在结束的过渡状态），单个群支持多个目标，但同一身份不能重复添加。
  - 普通用户被限制时，群内会发送一条公开状态消息，同时系统会利用 Telegram 的 `ephemeral_message_parameters` 向该用户发送一条仅其本人可见、带有专属“发言”按钮的临时入口；频道马甲身份则发送带按钮的公开状态。
  - 用户点击按钮后会弹出 Inline 模式输入框（预填 `gag:<目标 ID>`）。用户输入完成后发送的消息会附带隐藏验证参数。消息进入群聊后，机器人会严格校验目标 ID、群组 ID 与真实发送者，一旦发现身份伪造或跨群串扰，立即将违规消息直接删除。
- **动态字形混淆算法**：
  - 对文本逐字采样：以 `GAG_FILL_OPERATION_PROBABILITY` 概率进入字符填充逻辑（追加 `GAG_FILLER_MIN_DOTS` 至 `GAG_FILLER_MAX_DOTS` 个圆点，点之间以 `GAG_FILLER_GAP_SPACE_PROBABILITY` 概率插入空格），其余情况等概率替换为 `GAG_REPLACEMENT_CHARACTERS` 中的语气词字符。
  - 相同的混淆操作最多连续应用于 `GAG_MAX_CONSECUTIVE_SAME_OPERATIONS` 个相邻字形；对于极短文本，通过 `GAG_MIN_OPERATION_TIERS` 保底最少扰动字符数。
- **定时心跳与入口保活**：
  - 群内每产生 `GAG_SPEAK_NOTICE_MESSAGE_INTERVAL` 条常规消息，触发一次入口刷新通知，各会话独立计数。
  - 若目标用户连续 `GAG_SPEAK_NOTICE_IDLE_INTERVAL_MS` 未曾发言，其在下一次尝试发言时，系统会立即补发一条专属发言入口。
- **群注销处理**：当群组被 `/init disable` 或机器人被撤除管理员时，系统会平滑终止该群内的所有 gag 会话并撤回提示；若机器人已被踢出群聊，则直接释放会话占用的全局名额。

#### 6. 黑名单：`/block`
- **命令语法**：使用 `/block <目标> enable` 执行拉黑，使用 `/block <目标> disable` 解除拉黑。目标参数支持回复消息、`@username`、纯数字用户 ID 以及频道的负数 ID（仅解封支持频道 ID）。
- **影响范围**：执行拉黑后，目标会被写入本地 SQLite 权威黑名单表，并在机器人所管理的所有活跃群组中同步执行踢出与封禁。当机器人新加入群组或获得管理员权限时，会自动扫描并清理群内的黑名单成员。
- **异步批量处置**：执行拉黑确认持久化后，跨群封禁任务由后台异步并发推进，稍后在群内汇总播报成功与失败的群数统计；若已确证机器人在某些群内缺乏封禁权限，则不会向这些群发送无意义的 API 请求，直接计入失败群数。执行解除拉黑时，则在命令主线程中同步从数据库移出并在各群解除封禁后返回最终回执。
- **销号清理机制**：在后台巡检封禁过程中，若对某一目标的封禁探测连续 `BLOCKLIST_PARTICIPANT_INVALID_LIMIT` 次均被 Telegram 官方返回 `PARTICIPANT_ID_INVALID`（账号已注销），系统会自动将其判定为“已销号账号”，并从黑名单数据库中彻底注销该 ID。

#### 7. 广告检测与防冲群
- **`/ad_detect`（智能广告拦截）**：同一发送者在短时间内发送的消息会聚合为消息串，检测队列每隔 `AD_DETECT_QUEUE_TICK_MS` 抽取一批送入广告识别模型进行判定。一旦判定命中，立即按照 `/block` 同等标准执行永久拉黑并从群中踢出，同时在群内播发带有命中理由的封禁公告（30 秒自删）。纯网络代理节点链接（如 `vless://`、`vmess://`、`trojan://`、`ss://`）若不附带招募或营销导流文案，不会被误判为广告。
- **`/flood_control`（防连续刷屏）**：单个用户在超级群的 `FLOOD_WINDOW_MS` 滑动时间窗口内发送的消息条数达到 `FLOOD_MESSAGE_LIMIT` 时，系统将立即对其执行 `FLOOD_MUTE_DURATION_MS` 时长的临时禁言，并在群内播报警告（30 秒自删）。群管理员、频道身份不计入刷屏；拥有 `isCanBypassFloodControl` 权限的身份直接豁免。
- **`/antiraid`（入群验证与私密模式）**：开启后，新成员入群需在限时内完成人机验证挑战；在遭受集中冲群攻击时可联动进入私密防护。关闭该开关时，所有未完成的验证流程立即取消，发送的提醒消息同步撤回。广告拦截、防刷屏与全局黑名单不受此开关影响。
- **`/batch_kick`（批量清理新入群成员）**：仅超级管理员可用。通过分析入群事件日志，在指定的时间区间内（如 `30m`、`2h`、`1d`，必须在 `BATCH_KICK_MIN_DURATION_MS` 与 `BATCH_KICK_MAX_DURATION_MS` 范围内）批量踢出新加入的成员。只执行踢出操作，不加入黑名单；白名单身份与已在黑名单的身份均会自动跳过。命令受理后先行回复受理确认，踢人操作在后台异步执行并在完成后发送最终战报。

#### 8. 私聊中转与语音代发：`/send`
- 超级管理员在机器人私聊窗口中发送 `/send <群组 ID>` 开启中转；系统会先验证目标群的可达性，开启后管理员在私聊发送的所有普通消息均会被原样转发至目标群组。
- **语音代发模式**：在私聊中将整条消息以特定格式的 JSON 代码块发送，机器人会自动将其合成为语音气泡发送至目标群：
  ```json
  { "type": "tts", "tone": "需要的语气", "text": "需要转换的文本" }
  ```
  - 台词正文字数上限为 `VOICE_OPERATOR_TEXT_MAX_CHARS`，语气修饰词上限为 `VOICE_TONE_MAX_CHARS`（按 UTF-16 码元计算）。
  - 语音合成由后台异步执行，依赖在 `config/dynamic/agent.json` 中配置有效的 `agent.tts`。
  - 所消耗的配额走 `agent.tts.daily_reserve_quota` 独立预留配额（与定时任务共用，与常规 AI 闲聊的每日额度相互隔离）。

> [!TIP]
> **`/luck_challenge` 不是斜杠命令**：在任意聊天窗口输入 `@机器人用户名 [所求事项]` 即可调出 Telegram Inline 模式抽取今日运势。此功能需提前在 @BotFather 中开启机器人的 Inline Mode。该接口具备全局滑动窗口防刷保护：每个 `RATE_LIMIT_WINDOW_MS` 窗口内最多响应 `RATE_LIMIT_MAX_CALLS_PER_WINDOW` 次（常量定义见 `packages/consts/luckChallenge.ts`），超出时应答一条限流占位结果；当天运势密钥刷新失败时记错误日志并应答空结果。这两种应答都只让客户端缓存 `LUCK_INLINE_NO_DRAW_CACHE_SECONDS` 秒。

## 💍 群友老婆：`/wed`

在已执行 `/init enable` 的群组中，群成员发送 `/wed`（无需参数）即可抽取一名群友作为今日“老婆”。机器人会回复该命令并展示被抽取群友的当前头像，附带图注「发起人，你的群友老婆是 群友!」，消息下方带有交互操作按钮。按钮文案随通知语气配置动态变化：调侃风格下分别为「移除」「娶老婆!」「换一只」；克制风格下分别为「移除」「确认」「更换」，确认后状态展示为「已确认」。

| 按钮 | 功能行为 |
| :--- | :--- |
| **移除** | 撤回并删除当前抽取结果，释放本次会话 |
| **娶老婆! / 确认** | 锁定并确认当前结果，中间按钮更新为「已确认」；确认后仍可点击更换 |
| **换一只 / 更换** | 在同一条消息中重新抽取并更新头像和图注，自动排除发起人与当前目标，恢复确认按钮 |

### 核心运作机制

- **发起人独占**：抽取结果的消息按钮仅允许发起人本人点击交互。在重新抽取完成前点击旧按钮不会影响新目标。如果再次发送 `/wed` 命令，系统会开启新一轮抽取，待新结果发送成功后才会删除旧消息；若新消息发送失败则保留原结果；若旧消息删除失败，原消息仍会保留在群内但其按钮会失效。单个群内每位用户同一时间只保留一张可交互的结果卡片。
- **候选池构建与维护**：
  - 系统为每个群在内存中维护一个独立的、复用的 **`Set<number>`** 候选池，容量上限为 `WED_MEMBER_LIMIT`。
  - 仅收录在当前已初始化的群组中**以个人账号身份公开发言**的用户（自动忽略频道马甲、匿名管理员以及系统服务通知）。
  - 候选池达到人数上限后暂停收录新成员；当检测到成员退群事件时，立即从集合中移除其 ID。
  - 每天配置时区的 00:00，后台定时维护任务会通知主线程，主线程会以 `WED_MEMBER_REVIEW_INTERVAL_MS` 的防抖间隔逐一调用 Telegram `getChatMember` 接口复核候选池成员是否仍在群内（需管理员权限）；非管理员群组则依赖接收退群服务通知完成清理。
- **头像抓取与高效复用**：
  - 抽中候选人后，系统并发调用 `getChat`（获取当前公开资料）与 `getUserProfilePhotos`（获取前 `USER_PROFILE_PHOTOS_LIMIT` 张历史头像），通过 `big_file_unique_id` 精准比对确认当前正在使用的头像文件。
  - 比对成功后，直接复用 Telegram 已有的 `PhotoSize.file_id` 进行快速转发，机器人本地无需下载或重新上传任何图片；若未能匹配到已有文件，则回落为从 Telegram 下载头像并重新发送。
- **并发控制与容量**：
  - 所有的抽取与按钮点击统一排入主线程专用调度器：全局并发处理上限为 `WED_MAX_CONCURRENT`，排队队列上限为 `WED_MAX_PENDING`（遵循先进先出 FIFO 规则），队列已满时提示稍后再试。
  - 候选成员 ID 列表以 JSON 数组形式持久化在 `memory/wed/<chatId>.json` 中，由 Disk I/O Worker 批量写入（落盘条件见 [07 运维与排障](07-operations.md#数据根)）。
  - 单群同时并存的发起人会话上限为 `WED_SESSION_LIMIT`，系统管理群数上限为 `STATE_MANAGED_CHAT_LIMIT`，超出限制将拒绝新请求。抽取结果消息不挂固定 30 秒自动删除，仅由用户点击按钮或群组被注销时销毁。

## 🔎 查资料：`/info`

在已执行 `/init enable` 的群组中，任何成员均可通过 `/info` 查询某个指定身份的公开信息：回复其消息发送 `/info`，或输入 `/info @username`、`/info <用户 ID>`、`/info <频道/群组负数 ID>`。查询目标支持普通用户、广播频道、其他第三方 Bot 以及机器人自身。

- **展示信息**：显示公开昵称（普通用户为 `名 姓`，频道与群组为标题）、Telegram 用户名（未设置则标明）、数字 ID（支持点击直接复制）。若目标设置了公开头像，消息将附带其当前头像一同发出；无头像时会特别注明。
- **实时数据源**：每次查询均向 Telegram 实时发起请求。查询群内普通用户时读取其群成员资料，查询频道/群组时读取其会话信息，查询自身时直接读取本地配置。若实时请求失败，系统会回落使用解析出的缓存身份信息；若连昵称和用户名都无法解析，则回复“查不到”。头像获取逻辑复用 `/wed` 的机制（用户头像直接复用 file_id，频道头像下载后上传转发，必要时以公开 t.me 链接兜底），群组对象默认不展示头像。
- **生命周期与队列**：查询结果与错误提示消息均在 30 秒后自动清理。所有的查询请求交由全局共享的延迟执行器处理，单次查询超时上限为 `INFO_TASK_BUDGET_MS`；排队已满时回复“稍后再试”。在机器人私聊窗口中发送 `/info` 不做响应。

## 🖼️ 随机图片：`/h_image`

**图库配置**：图库本地目录由 `config/dynamic/assets.json` 中的 `onlyPath.random_h_image_dir` 指定（默认指向数据根目录下的 `./h_image`）。

在已执行 `/init enable` 的群组中，发送 `/h_image`（不带参数）即可从该专用图库中均匀随机抽选一张发送至本群。

- **文件格式过滤**：仅扫描图库根目录下的 `jpg`、`jpeg`、`png`、`webp` 格式文件（忽略隐藏文件、子目录及软链接）。若单张图片体积超出 `RANDOM_IMAGE_MAX_BYTES`，系统会自动跳过并重新抽取一张合规图片。往图库中手动增删图片无需重启服务，即时生效。
- **剧透遮罩保护**：抽取的图片默认全部开启 Telegram 剧透遮罩（`has_spoiler`），在群聊中以磨砂模糊图片呈现，用户需手动点击方可查看原图。
- **消息保留规则**：抽出的图片结果属于功能性内容，**长期保留**在群聊中不自动删除；参数错误提示、图库为空或未找到等错误提示消息则在 30 秒后自动删除。
- **并发与防刷保护**：
  - 共享延迟命令执行器的全局并发处理上限为 `DEFERRED_COMMAND_MAX_CONCURRENT`，排队等待槽位为 `DEFERRED_COMMAND_MAX_PENDING`。
  - 滑动窗口限流：与 `/h_image add` 及用法提示合并计算，在每个 `H_IMAGE_RATE_LIMIT_WINDOW_MS` 窗口内全实例最多处理 `H_IMAGE_RATE_LIMIT_MAX_CALLS_PER_WINDOW` 次，超额请求将直接静默丢弃。

### 收图：`/h_image add`

拥有 `isCanAddHImage` 权限的用户在群内回复一张包含图片的消息并发送 `/h_image add`，即可将该图片快捷收录进专用图库。

- **收录范围支持**：支持被回复消息中的原生大图（优先选取最高分辨率规格），以及以文件（Document）形式发送的 `jpg`、`png`、`webp` 图片。若被回复的消息属于某个相册（Media Group），机器人接收到的同一相册内的其余图片也会一并批量收录（单相册收录上限为 `MEDIA_GROUP_ITEMS_MAX`，内存相册组缓存上限为 `MEDIA_GROUP_CACHE_MAX`）。
- **内容寻址与天然去重**：
  - 写入图库的文件名严格以**图片二进制数据的 SHA-256 哈希值**命名，并保留原始文件头扩展名（如 `<64位哈希>.jpg`）。
  - 去重发生在下载后计算哈希阶段：如果图库中已经存在相同哈希的文件，系统会跳过重复写盘，并在回执中标记为“已存在”。
- **图片尺寸安全预检**：收图时会预先检查图片分辨率是否符合 Telegram `sendPhoto` 的限制：宽高之和不能超过 `TELEGRAM_PHOTO_MAX_DIMENSION_SUM`，宽高比不能超过 `TELEGRAM_PHOTO_MAX_ASPECT_RATIO`，超出规格的图片将被拒绝收录；超过体积上限 `RANDOM_IMAGE_MAX_BYTES`、格式不受支持或下载超时的图片均计入失败项。
- **写入原子性保证**：收录时先在图库同目录下写入以点号开头的临时文件，完全落盘校验后通过原子 `rename` 变更为最终文件名；抽图逻辑会自动忽略点号开头的临时文件。
- **批量并发与汇总回执**：批量收图按每组 `H_IMAGE_ADD_DOWNLOAD_BATCH_SIZE` 张分页并发下载，整页下载完毕后逐张校验写盘；整个收图任务的总时间预算为 `H_IMAGE_ADD_TASK_BUDGET_MS`，超时后未下载完的图片计为失败。收图完成后发送汇总战报（包括新收录张数、图库当前总数、重复跳过数、尺寸不合规数以及下载失败数），该回执在 30 秒后自动删除。

## ⏰ 定时发送：`cron.json`

定时任务由管理员在 `config/dynamic/cron.json` 中配置，支持运行时热重载，无需在群内通过命令操作。字段规范请参阅 [部署配置说明](../../config_example/README/zh.md#cronjson)，更多配置示例请参考 [08 图库与定时任务](08-images-and-cron.md)。

- **灵活的目标投放**：支持向指定的群组列表、所有已启用的活跃群组，或在全量广播中排除某些指定群组后，定时推送普通文本、图片相册、文件、语音气泡或联网搜索摘要。
- **图片与剧透设置**：固定图片可指定公网 `url` 或本地 `path` 数组，多张图片自动组装为 Telegram 相册发送，首图可附带说明文本；随机模式下每次抽选一张发送。`is_blurred` 属性可精确控制是否为图片添加剧透遮罩。
- **定时语音广播（`send_voice`）**：将配置的 `content` 文本按照可选的 `tone` 语气修饰词合成为语音气泡发出。此项依赖在 `agent.json` 中配置有效的 `agent.tts`，否则在配置校验阶段将被直接拦截报错。
- **AI 网页搜索摘要（`send_web_digest`）**：系统根据配置的简短 `topic` 检索相关主题，按照 `instructions` 的指导规则整理为符合 MarkdownV2 格式的精简摘要，返回条目数不超过 `max_items`。优先调用 `agent.web_search` 独立检索模型；若未配置，则回落至主文本模型内置的搜索能力；若模型未触发外部搜索，则会在发送正文前附带“注意，以下可能为模型侧缓存内容，请仔细甄别”的警示前缀。
- **生命周期与论坛路由**：定时消息发出后属于正式功能消息，长期保留；在开启了话题的超级群中，定时消息默认投递至 General 主话题中。一次性定时任务与随机浮动时间仅在内存中计时调度，若进程在预定触发时处于停机状态，重启后错过的任务不会补偿补发。
