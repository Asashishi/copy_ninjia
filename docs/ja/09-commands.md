## 🎭 Copy モード

copy 対象はグローバルで唯一です。同一インスタンスは同時に 1 つの対象にしか「変身」できませんが、copy 自体はコマンドを発行したグループでのみ発生します。`/copy stop` は任意のグループから現在の copy を停止できます。

| コマンド | 挙動 |
| :---: | :--- |
| `/copy` | 原文のまま復唱 |
| `/copy reverse` | 書記素クラスタ単位で文字とキャプションを反転 |
| `/copy nya` | 文字とキャプションの末尾に「喵~」を追加 |
| `/icon steal` | アバターのみコピー |
| `/icon reset` | アバターを Bot 本来のデフォルト画像に戻す |
| `/copy stop` | グローバル copy 状態を停止し、アバターも復元 |

### 送信と変換メカニズム

`/copy` 系とランダムな復唱は共通の送信ルールを使用します：
- **テキストとキャプション**：すべて文字列として扱い、リンクや @ を含むテキストも同様に変換します。純粋なテキストは再送信され、リンクと @username は Telegram によって再認識され、元メッセージのリンクプレビュー設定が引き継がれます。
- **フォーマットエンティティの制限**：太字、隠しリンク、ネタバレ（スポイラー）、カスタム絵文字などの書式は保持されず、スポイラーテキストも平文で送信されます。
- **リッチメディア処理**：画像、動画、ファイル、スタンプなどは Telegram サーバー側でそのまま複製され、キャプションがある場合は処理後のテキストに差し替えられます。ローカルホストには一切ファイルをダウンロードしません。有料メディアは複製できず、テキストのみを送信します。
- **純粋な非テキストメッセージ**：投票、ダイス、位置情報、連絡先などのテキストもファイルもないメッセージはそのまま複製されます。
- **長さ超過**：変換後に Telegram の本文またはキャプションの長さ上限を超えた場合はメッセージ全体を送信しません。

### 対象とパラメータの指定

対象は「対象のメッセージへの返信」または `@username` で指定します：
- **構文パターン**：モードは対象の前に記述します（例：`/copy reverse @username`、`/copy nya @username`）。アバターのみ変更する場合は `/icon steal @username` を使用します。`/copy stop` と `/icon reset` は追加パラメータを受け付けません。
- **ユーザー名観測への依存**：ユーザー名による検索は、Bot が過去にそのアカウントを観測している必要があります。改名、ユーザー名削除、ユーザー名の再割り当てが行われると、古いエイリアスは即座に無効化されます。`/block … enable` や `/block … disable` などの破壊的操作では、過去のユーザー名に頼らず、対象メッセージへの返信か、ユーザー ID の直接指定を優先してください。
- **匿名管理者**：現在のグループの身分として発言した場合、copy 対象は現在のグループ自身となり、グループのアバターを取得してその「外見」を再現できます。`/block` は現在のグループの身分をメンバー対象として扱うことを拒否します。
- **クールダウン制限**：`/copy`、`/copy reverse`、`/copy nya`、`/icon steal`、`/icon reset` は **5 分間のグローバルクールダウン**を共有します。`SUPER_ADMIN_USER_ID` 本人のみが免除され、ホワイトリスト（allowlist）身分もクールダウンの制限を受けます。`/copy stop` はクールダウンを消費しません。

## 🌐 群ごとの翻訳

翻訳はテキストとキャプションを処理し、グローバルな copy 対象、5 分間のクールダウン、アバター操作から独立しています。あらかじめ `isCanControllTranslatePermission` を持つ身分が `/translate enable` を実行し（デフォルト無効）、有効な `g-auth.json` を提供しておく必要があります。他の Bot の通常メッセージを翻訳する場合は、@BotFather で本 Bot の Bot-to-Bot Communication Mode を有効にします。受信したメッセージも[他の Bot の入口制限](04-invariants.md)の対象です（[01 環境構築](01-getting-started.md) を参照）。

| コマンド | 挙動 |
| :--- | :--- |
| `/translate ja` | 対象メッセージに返信し、以降のテキストを日本語へ翻訳 |
| `/translate cn @username` | 観測済みのユーザー名で対象を指定し、簡体字中国語へ翻訳 |
| `/translate en` | 対象メッセージに返信し、米国英語へ翻訳 |
| `/translate uk` | 対象メッセージに返信し、ウクライナ語へ翻訳 |
| `/translate ru` | 対象メッセージに返信し、ロシア語へ翻訳 |
| `/translate list` | 正規表現判定に対応している言語を JSON コードブロックで一覧表示 |
| `/translate stop` | 返信や対象の指定がない場合、本グループの全セッションを停止（機能スイッチは保持） |
| `/translate stop @username` または `/translate stop 123456789` | 指定した対象のみ停止。対象メッセージへの返信やチャンネルの負数 ID も指定可能 |
| `/translate disable` | 本グループの全セッションを削除して翻訳機能を無効化。翻訳管理権限が必要 |

### セッション容量と排他ルール

- **セッションクォータ**：グループメンバーがセッションの開始・停止を行えます。1 グループにつき最大 5 つの異なる身分を保持し、各身分で翻訳方向を独立して選択可能、全体で最大 25 グループまで管理します。上限超過時は新規開始を拒否し、既存セッションの追い出しは行いません。同一身分の翻訳方向を変更する前に、まずその身分のセッションを停止してください。
- **衝突処理**：返信対象とパラメータが衝突した場合は拒否し、グループ全体の停止にはフォールバックしません。
- **copy との排他**：`/copy stop` は翻訳を停止しません。同一身分が copy と翻訳の両方の対象に該当する場合、**翻訳のみを実行**します（復唱、メディアの複製、リアクションの同期は行いません）。他の copy 対象は通常通り動作します。

`/translate list` の内容は以下の通りです。Telegram の `pre` エンティティかつ `json` タグ付きで送信され、グループ内では 30 秒後に削除されます：

```json
{
  "ja": "日语",
  "cn": "简体中文",
  "en": "美式英语",
  "uk": "乌克兰语",
  "ru": "俄语"
}
```

### 言語判定と送信ルール

- **事前フィルタリングルール**：テキストとキャプションはすべて文字列として翻訳され、リンク、@、フォーマットエンティティを含むテキストも同様に翻訳されます。正規表現によって翻訳先言語の文字種であると判定された場合や、数字・約物・絵文字のみのテキストである場合は、翻訳 API を呼び出さず、メッセージ全体を送信しません。
  - **日本語**：仮名を必須とします。
  - **簡体字中国語**：Unicode Unihan において簡化変体を持つ繁体字を除外します。
  - **英語**：ASCII 文字を受け入れます。米国英語は `en-US` に対応した [Google Translation LLM](https://docs.cloud.google.com/translate/docs/languages#translation-llm) を使用します。
  - **ウクライナ語**：固有の字母とアポストロフィを受け入れ、ロシア語の `ёъыэ` を除外します。
  - **ロシア語**：`Ё/ё` を受け入れ、ウクライナ語の `єіїґ` を除外します。
  - *注*：共通の漢字、アクセント記号のないラテン文字、共通のキリル文字による短文では言語判定に曖昧さが残る場合があり、正規表現は意味解析レベルの言語識別を行うものではありません。
- **送信形式**：翻訳は訳文のみを送信し、原文は送信せず、メディアも複製しません。翻訳 API が失敗した場合や、訳文が原文と一字一句同一である場合は、メッセージ全体を送信しません。
  - 訳文は文字列として送信され、書式は保持されず、テキストメッセージは元メッセージのリンクプレビュー設定を引き継ぎます。
  - キャプション付きの画像、動画、音声、ファイル、有料メディアは、キャプションの訳文のみをテキストとして送信し、メディア自体は複製しません。
  - テキストのない画像、スタンプ、ファイルや、投票・位置情報などのメッセージは送信されず、同一対象の copy にフォールバックすることもありません。
  - 訳文が本文の長さ上限を超えた場合は送信しません。トピック（フォーラムスレッド）は保持し、表示可能なコマンドは拒否します。コマンド通知は 30 秒後に削除されます。
- **永続化状態**：セッションは SQLite `chat_states` の本グループ行の `translate` 配列に保存されます。単一対象の停止はその対象のみを取り消し、他者の追加や停止によって処理中の翻訳が取り消されることはありません。機能無効化やグループの teardown 時は全セッションを削除し、非同期処理の結果は送信前に対象のセッションオブジェクトを再確認します。`/bot_status` には本グループで翻訳を利用している `人数/5` が表示されます。

| `/bot_status` | `isCanViewBotStatus` | プロセス指標、グローバルモデル能力、Telegram 429 送信キュー、AI コンテキスト容量、有効な gag 数、本グループの翻訳人数（最大 5 人）、本グループで Bot が現在持つ権限（JSON ブロック）、本グループの各機能スイッチの真偽（JSON ブロック、無効な項目も false として列挙）を表示 |
| `/init enable\|disable` | `SUPER_ADMIN_USER_ID` | 本グループの主要業務処理ゲートの切り替え |
| `/batch_kick <Nm\|Nh\|Nd>` | `SUPER_ADMIN_USER_ID` | スーパーグループにおいて、ローリング 24 時間以内の指定時間枠に参加し、現在も在籍しているメンバーをキック（BAN は行わない） |
| `/send <グループ ID>`<br>`/send finish` | `SUPER_ADMIN_USER_ID`（個人チャット限定） | Bot との個人チャットから指定グループへの転送セッションを開始/終了。転送中に TTS リクエストをメッセージ全体のコードブロックとして送信すると、Bot がボイスメッセージとして発声 |

> [!IMPORTANT]
> **権限列の読み方**：
> - `isCanXxx` と記載された行は権限キーに基づいて認可されます。`SUPER_ADMIN_USER_ID` 身分自体は恒常的に**全権限キー**を保持しているため、SQLite のホワイトリストテーブルにエントリがなくても、これらのコマンドはすべて使用可能です。
> - `SUPER_ADMIN_USER_ID` と記載された行は、**その身分本人のみが実行可能であり、ホワイトリストによって委任・付与することができない**厳格な境界です。

### パラメータと対象のマッチング規約

- **フォーラムトピックメッセージの扱い**：フォーラムトピック作成時に自動挿入される作成メッセージへの返信は「明示的な返信なし」として扱われ、コマンドはパラメータによって対象を指定できます。その作成メッセージ自体への明示的な返信も同一のルールで処理されます。連携チャンネルのディスカッショングループにおけるコメント返信は正常に保持されます。
- **ポリシーのプリフェッチ**：ブラックリスト・ホワイトリストに依存する身分の変更やメンバー操作は、あらかじめポリシーのプリフェッチが完了している必要があります。失敗した場合は一時的な案内通知のみを返し、処理を中断します。
- **統合エントリメニュー**：チャットのコマンドメニューにおいて、`/copy`、`/qa`、`/mood`、`/icon` は統合エントリとして登録され、説明欄に各パラメータが記載されます。サブコマンドが欠落しているか不正な場合は、使い方案内のみを返信します。
  - `/qa set`、`/mood query`、`/mood switch` は追加パラメータを受け付けません。
  - `/qa query` は質問を省略すると全件を一覧表示し、`/qa remove` は質問の指定が必須です。照会と削除のいずれも、質問テキスト内の空白や改行を保持します。
- **サブコマンドの大文字・小文字**：`/copy stop|reverse|nya`、`/icon steal|reset`、`/qa set|remove|query`、`/translate <方向>|stop`、`/mood query|switch`、`/h_image add` のサブコマンド語は、いずれも大文字・小文字を区別しません（`/block`、`/white`、`/init` の口径と一致）。サブコマンド語の後に続く対象パラメータや質問テキストは、元の大文字・小文字を保持し、正規化されません。
- **ボタンコールバックの検証**：参加認証、`/wed`、`/qa query` ボードのページ送りにおける `callback_data` 内の数値文字列は、正規の十進数として厳格に解析されます（正符号、先頭のゼロ、空白、小数点、指数表記は不可）。本 Bot が生成するボタンは正規の十進数のみであり、それ以外の形式は即座に「ボタン無効」として応答されます。

### 挙動の詳細

#### 1. 人設と通知口調
- 人設（ペルソナ）はプロセスレベルのデプロイ入力であり、グループ単位で設定するコマンドはありません。
- AI ペルソナはプロジェクトルートの `prompt/persona.md` の本文を使い、ファイルがなければ内蔵の雌小鬼人設を使います。コマンド通知、権限 help、ボタン、自動通知、コマンドメニュー、inline 運勢は `config/static/bot.json` の明示した `atmosphere`（`mesugaki` 雌小鬼版、`normal` 通常版）を優先します。省略時はカスタム人設なら通常版、内蔵人設なら雌小鬼版です。
- いずれも起動時に確定し、変更は再起動後に反映されます。AI スイッチのオン/オフは選択に影響しません。
- 起動時は全グループチャットスコープ（`all_group_chats`）のメニューのみを登録し、デフォルトスコープを削除するため、個人チャットにはメニューが表示されません。個人チャットのコマンドはスーパー管理者の `/send` にのみ応答します。

#### 2. `/bot_status` 指標収集
- **モデル能力**：設定が準備できている能力だけを「能力名：モデル名」で列挙します。モデル名は最後の `/` より前の名前空間を省き、xAI の音声合成はモデル名の代わりに音色を表示します。画像生成・音声合成・独立したウェブ検索が未設定の場合、および AI チャット・広告検出の設定が未準備の場合は、該当する行を表示しません。列挙できる能力がない場合はモデル能力のセクション全体を省きます。
- **メモリ使用量**：コマンド受信時に `Bun.unsafe.memoryFootprint()` を呼び出し、Bot プロセス全体（Worker を含む）の現在のメモリ使用量を表示します。Linux では PSS を使用し、共有常駐ページはプロセス間で按分されます。使用率の分母はコンテナのメモリ制限値とし、制限がない場合はホストマシンの物理メモリ総量を使用します。サンプリングできない場合は「利用不可」と表示されます。
- **本グループのコンテキスト容量**：スライディングホットメモリは `VERBATIM_CONTEXT_MAX`（256 件）、コールドメモリ要約は `MAX_SUMMARY_ROUNDS`（7 ラウンド）で使用率をそれぞれ算出し、7:3 で加重合計した**単一のパーセンテージのみを表示**します。2 つのカウント値は AI Worker がメモリ snapshot 報告（周期 `AI_SNAPSHOT_INTERVAL_MS`、30 秒）に乗せて送信し、hydrate 完了後に全量シードされます。メインスレッドは読み取り専用のミラーを保持するのみです。未昇格の要約はコールド領域にカウントされず、ミラーにエントリが存在しない場合は一律 0 と表示され、読み取り値は最大で 1 報告周期分遅延します。

#### 3. アクションコマンドと /x
- 名前は `first_name last_name` の形式を使用し、公開ユーザー名を持つ側にはプロフィールへのリンクが付与されます。対象は「相手のメッセージへの返信」または `@username` で指定します。
- 成功したアクション結果は、`/permission help` や `/permission query` と同様に長期保持されます。対象の欠落、パラメータエラー、`/x` の使い方案内は 30 秒後に削除されます。

> [!TIP]
> **漢字 1~2 文字のアクションコマンドは事前登録が不要**で、任意の 1~2 文字の漢字が使用可能です。Telegram のコマンド名は ASCII のみを受け付けるため：
> - これらのコマンドはコマンドメニューに表示されず、入力補完も効きません。メニューにはプレースホルダーとしての説明項目 `/x` のみが配置されており、これをタップすると使い方案内を受信して処理が終了します。
> - `/咬人人` のような 3 文字以上の表記はアクションコマンドとして扱われず、通常のメッセージとして処理されます。
> - グローバルなスライディングウィンドウによるレート制限：グループやユーザーを区別せず合算して、90 秒あたり最大 450 回まで応答します。超過分は静かに破棄されます。

#### 4. グループ Q&A：/qa ライフサイクル
- **フォーム収集メカニズム**：
  - `/qa set` のフォームは**フォーマットメッセージ**によってテキストを収集します。フォーム発行時に `isCanControllQaPermission` を検証し、以降はフォームを開いた身分本人のみを認識します（チャンネル身分や匿名管理者も同様にサポート）。
  - 投稿フォーマットは行頭の `问题:` または `回答:`（半角・全角コロンどちらも可、`答案:` も同義）とし、2 通に分けて送信するか、1 通にまとめて送信します。
  - 回答内の ```` ```json ```` コードブロックは**リテラルのフェンス**として保存され、直接応答時に元の形式に展開されて送信されます。フェンス自体も 3840 文字の上限にカウントされます。
  - 受理された投稿メッセージは削除され、メッセージパイプラインには流れません。フォームはインプレースで書き換えられ、現在の状態が表示されます。2 つの項目の合計が Telegram の単一メッセージ制限（4096 文字）を超える場合、回答の表示は残りの文字数予算に合わせて切り詰められ、省略記号が付与されます（データベースに登録されるのは完全な原文です）。
- **並行処理とリセット**：
  - フォームはグループごとに唯一であり、15 分のタイムアウトで自動回収されます。同一項目を再送信した場合は古い値が上書きされます。同一人物が再度 `/qa set` を送信すると古いフォームは破棄されて再作成されます。他のメンバーが記入中に `/qa set` を送信した場合はその場で拒否されます。
  - `/init disable` や Bot のグループ退出時は、本グループの全 Q&A がデータベースから削除されます（管理者権限が剥奪されたのみの場合は Q&A 記録は保持されます）。
- **ボードのページネーションと直接応答**：
  - `/qa query` ボードは固定で 1 ページ 3 件とし、ページ送りボタンを提供してインプレースでメッセージを書き換えます。各クリック時に `callback_data` のページ番号に基づいてホットテーブルから再読み込みされ、回答は 256 文字に切り詰められます（**質問は決して切り詰められません**）。
  - **Q&A 直接応答**：メッセージテキストが登録された質問と一字一句違わず一致する場合（先頭の `@Bot` を除去後）、AI を介さず即座に回答します（ランダムな割り込みの制約を受けません）。意味は類似していてもテキストが異なる質問は、AI の `group_qa_query` および `group_qa_answer` ツールによって雑談ラウンド内で検索・応答されます。

#### 5. 発言制限：/gag
- **容量と入口メカニズム**：
  - グローバルで同時に有効な対象は最大 5 件です。同一グループ内に複数の対象を配置できますが、同一の身分を重複させることはできません。
  - 通常ユーザーに対してはグループ内に公開ステータスを残し、`ephemeral_message_parameters.receiver_user_id` で限定された本人にのみ見える「発言」ボタン付きの一時的な入口を送信します。チャンネル身分に対してはボタン付きの公開ステータスを送信します。
  - ボタンには `gag:<対象 Telegram ID>` があらかじめ入力されます。生成結果は隠しテキストリンク内に `<対象プロフィール>#<セッショングループ ID>` を保持します。メッセージがグループに着信後、対象、グループ、実際の送信身分を同時に検証し、不一致の場合は即座に削除します。
- **レンダリングと難読化アルゴリズム**：
  - 書記素（拡張グラフェム）ごとにサンプリングを実施：75% はパディング分岐に進み（3~6 個のドットを追加、隣接ドット間は 1/3 の確率でスペースを挿入）、25% は等確率で 6 種類の擬音文字のいずれかに置換されます。
  - 同種の操作が連続して適用されるのは隣接する最大 2 つの書記素までです。短いテキストには最低操作数の保証があります（2~3、4~7、8~31、32~64 書記素に対してそれぞれ最低 2、3、7、15 回の操作）。
- **ハートビートとリフレッシュメカニズム**：
  - グループメッセージ **7 件**ごとに 1 回入口のリフレッシュがトリガーされます。
  - ユーザー専用入口は初回アクティベーション時および各リフレッシュ完了後に **30 秒**待機して再送信されます。対象が連続して **45 秒**発言しなかった場合、次回の発言時に即座に再送信されます。

#### 6. ブラックリスト：/block
- **操作構文**：`/block <対象> enable` でブラックリスト登録、`/block <対象> disable` で解除。対象は返信、`@username`、ユーザー ID（正の整数）、およびチャンネル負数 ID（解除のみ対応）をサポートします。
- **有効範囲**：ブラックリスト登録後は正規の SQLite ブラックリストに書き込まれ、Bot が管理するすべてのグループにおいて即座にキック/BAN されます。Bot が管理者権限を取得してグループが初期化された際にも、グループ内のブラックリストメンバーが自動的にスキャン・処分されます。
- **アカウント削除のクリーンアップ**：グループ内での BAN 処理時に対象が 5 回連続して `PARTICIPANT_ID_INVALID` を返した場合、アカウント削除済みと判定され、ブラックリストから自動的に除外されます。

#### 7. 広告検出と荒らし対策
- **`/ad_detect`**：メッセージは送信者（`chatId:senderId`）ごとにバンドルされ、キューが毎秒 1 バッチを取得して `agent.ad_detect` モデルに判定を委ねます。広告と判定された場合は保護対象外の身分に対して `/block` と同等の処分を実施し、グループ内に BAN 理由を通知します（30 秒後に自動削除）。純粋なプロキシリンク（`vless://`、`vmess://`、`trojan://`、`ss://`）であり募集・宣伝文を含まない場合は広告と判定されません。
- **`/flood_control`（連投制限）**：同一人物が同一スーパーグループ内で 1 分間に 15 件発言した場合、その場で 3 分間ミュートし、グループ内に告知します（30 秒後に自動削除）。管理者やチャンネル身分はカウント対象外です（免除判定は `isCanBypassFloodControl` を参照）。
- **`/antiraid`**：参加認証と Anti-Raid 非公開モードを有効化します。無効化時は両方のパイプラインイベントが完全に停止し、送信済みの認証リマインダーは即座に取り下げられます。広告検出、連投制限、ブラックリストには影響しません。
- **`/batch_kick`**：スーパー管理者のみ利用可能。参加ログに基づき、指定された時間枠（例：`30m`、`2h`、`1d`、≤ 24 時間）内に参加した新規メンバーをキックします（BAN は行わず、ホワイトリストおよびブラックリスト身分はスキップされます）。

#### 8. プライベート中継と音声代行：/send
- 開始前に対象グループへの到達可能性を検証し、中継期間中はスーパー管理者が個人チャットで送信した各メッセージがそのまま対象グループへ転送されます。
- **音声代行**：メッセージ全体を以下の JSON コードブロックとして送信します：
  ```json
  { "type": "tts", "tone": "望む口調", "text": "変換するテキスト" }
  ```
  - セリフ上限 256、口調上限 64（UTF-16 コード単位）。
  - 音声合成はバックグラウンドで非同期実行され、`config/dynamic/agent.json` 内に `agent.tts` の設定が必要です。
  - クォータは `agent.tts.daily_reserve_quota`（デフォルト 25 回、AI 雑談クォータとは隔離）を共有します。

> [!TIP]
> **`/luck_challenge` はスラッシュコマンドではありません**：任意のチャットで `@Botのユーザー名 [お願い]` と入力することで Inline Mode によるおみくじ（運勢抽選）を利用できます。BotFather で Inline Mode を有効化しておく必要があります。グローバルなスライディングウィンドウによるレート制限：90 秒あたり最大 300 回まで応答します。

## 💍 グループ嫁：/wed

グループで `/init enable` が実行された後、グループメンバーがグループ内で `/wed`（引数なし）を送信します。Bot はコマンドに返信して抽選されたユーザーのアバターを送信し、キャプションに「実行者，你的群友老婆是 メンバー!」と表示し、下部にインタラクティブボタンを提供します：

| ボタン | 挙動 |
| :--- | :--- |
| **移除** | この結果を削除してセッションを解放 |
| **娶老婆!** | 現在の結果を確定し、中央ボタンを「已确认♡」に変更（引き続き再変更可能） |
| **换一只** | 同一メッセージ内でアバターとキャプションを変更（実行者および現在の対象を除外し、確定ボタンを復元） |

### 中核動作メカニズム

- **操作の排他性**：結果は実行者本人のみが操作できます。変更前の古いボタンをクリックしても新しい対象には作用しません。再度 `/wed` を送信すると再抽選が行われ、古い結果は削除されます。各グループにおいてユーザー 1 人につき 1 件の結果のみが保持されます。
- **候補プールの構築**：
  - グループごとに独立し、長期的に再利用される **`Set<number>`（上限 15 万人）**。
  - 初期化済みグループにおいて**個人身分**で実際に発言したユーザーのみを記録（チャンネル、匿名管理者、サービスメッセージは記録されません）。
  - 上限到達時は新規追加を停止します。退室更新を受信した場合は即座に集合から該当 ID を削除します。
  - 毎日設定タイムゾーンの時刻 00:00 に、Bun cron がメインスレッドをトリガーし、毎秒最大 5 ID のレートでグループメンバーを再確認します（管理権限による `getChatMember` が必要）。非管理者グループでは退室サービスメッセージによるクリーンアップに依存します。
- **アバターの取得とキャッシュ**：
  - 候補が選出された後、`getChat` を呼び出してプロフィールを取得し、`getUserProfilePhotos` の先頭 100 枚から `big_file_unique_id` に基づいてサイズをマッチングします。
  - マッチング成功時は `PhotoSize.file_id` を再利用して直接転送し、ローカルでのダウンロードやアップロードは行いません。マッチしなかった場合は現在の ChatPhoto をダウンロードして送信します。
- **並行処理とレート制限**：
  - コマンドとボタンはメインスレッドの実行器を共有します：グローバルで同時に最大 **32 件**まで並行処理し、キュー上限は **512 件**（FIFO）です。満杯時は後ほど再試行するよう案内します。
  - メンバー ID リストは JSON 配列として `memory/wed/<chatId>.json` に保存され、累計 256 件の変更または 30 秒経過後に DiskIO によってバッチ書き込みされます。
  - セッションは 1 グループにつき最大 512 件保持し、上限到達時は新規グループを拒否します（最大 25 グループ）。結果メッセージには 30 秒削除を適用せず、ボタン操作またはグループの teardown によって破棄されます。

## 🔎 ユーザー情報照会：/info

グループで `/init enable` が実行された後、誰でも `/info` を使用して身分の公開プロフィールを照会できます：対象のメッセージに返信して `/info` を送信するか、`/info @username`、`/info <ユーザー ID>`、`/info <チャンネルまたはグループ ID>` と入力します。対象はユーザー、チャンネル、他の Bot、または Bot 自身を指定可能です。

- **返却内容**：名前（ユーザーは `first_name last_name`、チャンネル/グループはタイトル）、ユーザー名（存在しない場合は明記）、ID（タップしてコピー可能）。アバターが存在する場合はアバターを添付し、存在しない場合はその旨を明記します。
- **データソース**：毎回その場で照会します。ユーザーはグループ内のメンバー情報、チャンネル/グループはチャット情報、Bot 自身は自身の情報を読み取ります。アバターは `/wed` と同一の取得ロジックを再利用します（ユーザーアバターは file_id を再利用、チャンネルアバターはダウンロードしてアップロード、t.me をフォールバックとして利用）。
- **保持と制限**：応答およびエラー案内はすべて **30 秒後に削除**されます。照会は共有の遅延コマンド実行器へ渡され、キューから取り出した後の 1 回の照会の予算は 30 秒です。キュー満杯時は「後ほど再試行」と返信します。個人チャットでの `/info` には応答しません。

## 🖼️ ランダム画像：/h_image

**画像ライブラリ設定**：`config/dynamic/assets.json` の `onlyPath.random_h_image_dir`（デフォルトは `./h_image`、実行時データルートからの相対パスとして解決）。

グループで `/init enable` が実行された後、`/h_image`（引数なし）を送信すると、画像ライブラリから均等にランダム抽選された 1 枚が本グループへ送信されます。

- **フォーマットとフィルタリング**：ライブラリ直下の `jpg`、`jpeg`、`png`、`webp` のみを認識します（隠しファイル、サブディレクトリ、シンボリックリンクは無視）。ファイルサイズが 10 MB を超える場合は自動的にスキップして再抽選します。画像の追加や削除に再起動は不要です。
- **ネタバレ（スポイラー）マスク**：結果の画像は常に Telegram のスポイラーマスク（`has_spoiler`）が付与され、ぼかし画像として送信され、タップすることで展開されます。
- **保持ルール**：画像は**長期保持**されます。不正なパラメータの使い方案内、ディレクトリの空/不在/サイズ超過などのエラー案内は **30 秒後に削除**されます。
- **並行処理とレート制限**：
  - 遅延コマンド実行器によりグローバル並行 **2 件**、待機キュー **16 件**。
  - スライディングウィンドウ制限：`/h_image add` と合算して 1 秒あたり最大 **5 回**まで受理し、超過分は静かに破棄されます。

### 画像収集：/h_image add

`isCanAddHImage` 権限を持つ身分が画像付きメッセージに返信して `/h_image add` を送信することで、画像をランダム画像ライブラリに収録できます。

- **収録範囲**：返信先メッセージの原画像（最大サイズ）、またはファイル形式の `jpg`/`png`/`webp`。アルバムに属する場合、Bot が観測済みの同一組の残りの画像もまとめて収録します（単一アルバムの上限 10 枚、メモリ内に直近 256 個のアルバムをキャッシュ）。
- **コンテンツアドレッシングと重複排除**：
  - ファイル名は厳格に**画像バイナリコンテンツの SHA-256** にファイルヘッダーに基づく拡張子を付与した形式（例：`<hash>.jpg`）を採用します。
  - 重複排除はダウンロード後のハッシュ計算時に行われます：ライブラリ内に同一ハッシュのファイルが既に存在する場合、既存である旨を案内し、ディスクへの重複書き込みは行いません。
- **サイズコンプライアンス制限**：Telegram の `sendPhoto` 制限である幅と高さの合計 ≤ 10000、アスペクト比 ≤ 20 を満たす必要があります。収録時にサイズを事前検査し、制限を超過した画像は収録を直接拒否します。
- **ディスク書き込みの安全性**：まずドットで始まる名前の一時ファイルとして書き込み、完了後に同一ディレクトリ内でアトミックに `rename` することで、画像抽選処理が書き込み途中のファイルを読み取ることを防ぎます。
- **処理結果とタイムアウト**：実行上限は 120 秒です。完了後に集計レポート（収録数、元のライブラリ枚数、スキップ数、サイズ超過数）を送信し、案内は 30 秒後に削除されます。

## ⏰ 定時送信：cron.json

定時タスクは運用者が `config/dynamic/cron.json` に設定し、ホットリロードに対応しています（グループ内での編集コマンドはありません）。

- **配信スコープ**：指定チャット、有効化済みで送信権限を持つ全グループ、または一部を除外したグループ集合に対して、テキスト、画像、ファイル、音声を送信できます。
- **画像とマスク**：固定画像は 1–10 項目の `url` またはローカル `path` に対応（2–10 枚は自動的にアルバムとして構成され、先頭画像にキャプションが付与されます）。ランダムモードは毎回 1 枚送信されます。`is_blurred` スイッチにより画像のスポイラーマスクを制御します。
- **音声ブロードキャスト（`send_voice`）**：`content` を任意の `tone`（口調）に従って音声バブルに合成して送信します。`agent.json` 内で `agent.tts` が設定されている必要があり、設定されていない場合は起動拒否またはホットリロード拒否となります。
- **ウェブ要約（`send_web_digest`）**：短い `topic` を検索し、`instructions` のタスク規則に従って最大 15 項目の MarkdownV2 要約にまとめます。項目本文は改行できます。`agent.web_search` を優先し、未設定なら `text` の組み込み検索を使います。モデルが検索しなかった場合は、固定警告「注意，以下可能为模型侧缓存内容，请仔细甄别」を付けて本文を送信します。
- **ライフサイクル**：定時メッセージは長期保持され、フォーラムグループでは General トピックに送信されます。単発タスク（`just_once`）やランダム時刻はメモリ内でのみ管理され、停止期間中にスキップされたタスクは補填送信されません。詳細な設定仕様は [デプロイ設定説明](../../config_example/README/ja.md#cronjson) を参照してください。
