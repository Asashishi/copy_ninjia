本ページでは、専用画像ライブラリの準備、画像収集、定時画像・アルバム・音声の設定を説明します。全フィールドの仕様は [デプロイ設定説明](../../config_example/README/ja.md)、コマンドの権限と挙動は [09 コマンドリファレンス](09-commands.md) を参照してください。

## 専用画像ライブラリの準備

`config/dynamic/assets.json` にライブラリのディレクトリを指定します：

```json
{
  "onlyPath": {
    "random_h_image_dir": "./h_image"
  }
}
```

- 絶対パス、または `./`・`../` で始まる相対パスを使います。相対パスは実行時データルートを基準に解決します。データルートの設定は [07 運用マニュアル](07-operations.md) を参照してください。
- サービスアカウントにはディレクトリの読み取り・書き込み・走査権限が必要です。起動時に存在しないディレクトリを作成でき、既存ディレクトリ内のファイルは厳密に検証されます。
- 専用ライブラリには通常の画像ファイルを置き、内容の 64 桁の小文字 16 進 SHA-256 に `.jpg`、`.jpeg`、`.png`、`.webp` の拡張子を付けて命名します。サブディレクトリ、ファイルのシンボリックリンク、不正な名前がある場合は起動を拒否します。
- `/h_image add` は内容のハッシュ計算と命名を自動で行い、同じ内容が既にある場合は書き込みを省略します。画像を追加・削除すると、後続の抽選は現在のディレクトリ内容を読み取ります。

パスの詳しい規則は [assets.json](../../config_example/README/ja.md#assetsjson) を参照してください。

## 画像の収集と抽選

1. スーパー管理者が対象グループで `/init enable` を実行します。
2. `isCanAddHImage` 権限を持つユーザーが画像メッセージに返信して `/h_image add` を送ります。同じアルバム内で Bot が受信済みの画像もまとめて収録します。
3. 集計結果の収録済み・既存・サイズ不適合・失敗の件数を確認します。
4. グループで `/h_image` を送ると、専用ライブラリから 1 枚をランダムに抽選します。結果には常に Telegram のスポイラーマスクが付き、タップすると表示されます。

対応画像形式、サイズ制限、コマンドのレート制限、通知の保持規則は [ランダム画像コマンド](09-commands.md#random-images) を参照してください。

## 定時画像の送信

定時タスクは `config/dynamic/cron.json` のタスク配列に設定し、ホットリロードに対応しています。以下は指定したタイムゾーンで毎日、専用ライブラリから 1 枚を抽選する例です：

```json
[
  {
    "name": "daily-library-image",
    "chat_id": [-1001234567890],
    "cron": "0 12 * * *",
    "time_zone": "Asia/Tokyo",
    "actions": [
      {
        "type": "send_image",
        "payload": {
          "rand_image": true,
          "content": "今日のランダム画像",
          "is_blurred": true
        }
      }
    ]
  }
]
```

例のグループ ID を実際の対象グループ ID に置き換え、時刻とキャプションを設定してください。タスク名はファイル内で一意にし、アクションは `actions` の宣言順に実行されます。

### 単画像・アルバム・ランダム画像

| 送信方式 | `send_image.payload` の画像ソース |
| --- | --- |
| 固定の単画像 | `url: ["https://example.com/a.jpg"]`、または `path: ["./posters/a.jpg"]` |
| 固定アルバム | `url` または `path` の配列に複数の画像ソース |
| 専用ライブラリのランダム画像 | `rand_image: true`、`path` は省略 |
| 任意ディレクトリのランダム画像 | `rand_image: true` とディレクトリ文字列、例：`path: "./gallery"` |

固定画像の `url` と `path` は排他的で、1 枚でも配列を使います。複数画像はアルバムとして送信します。ランダムモードの `path` はディレクトリ文字列で、任意ディレクトリ内の画像には SHA-256 命名を要求しません。`is_blurred` が定時画像のスポイラーマスクを制御し、省略時は無効です。

### 時刻と送信先

- `cron` は 5 フィールドの式、または `@daily` などのマクロです。`time_zone` は IANA タイムゾーン名で、省略時は `config/static/bot.json` の `time_zone` を継承します（Bot の既定値は `Asia/Tokyo`）。
- `rand_cron` は各トリガー後のランダム実行区間、例：`"6h-12h"` を設定します。`just_once: true` は現在のプロセス実行中に 1 回だけ実行します。両者は同時に使えません。
- `chat_id` はグループ ID の配列を指定できます。`["all"]` は有効化済みで送信権限を持つ全グループ、`["except", -1001234567890]` はその集合から指定グループを除外します。

## 定時音声とその他のアクション

定時音声には、先に `config/dynamic/agent.json` の `agent.tts` を設定します。タスクの `actions` に以下のアクションを追加します：

```json
{
  "type": "send_voice",
  "payload": {
    "content": "おやすみ、また明日ね",
    "tone": "小声で"
  }
}
```

音色は `agent.tts.voice`、この台詞の話し方は任意の `tone` で指定します。同じ実行回で複数グループへ送る場合、最初に合成した音声を再利用します。フィールドの仕様は [デプロイ設定説明](../../config_example/README/ja.md#agentjson) を参照してください。

タスクは `send_message`、`send_file`、`send_web_digest` にも対応します。アクションのフィールド、能力の依存関係、文字数と件数の上限は [cron.json](../../config_example/README/ja.md#cronjson) を参照してください。

## 動作確認と実行中の変更

ライブラリのパス、サービスアカウントのアクセス権限、グループの初期化と送信権限を確認し、画像収集と抽選の結果を確かめます。定時タスクの設定後はタイムゾーンと予定時刻を照合し、ログと対象グループへの実際の送信を確認してください。

`assets.json`、`cron.json`、`agent.json` はホットリロードに対応します。タスク名で差分を照合し、変更のないタスクは既存のスケジュールを維持します。起動検証、ホットリロード、メッセージのトピック、停止の制約は [04 正式な不変条件](04-invariants.md)、ライブラリ形式の移行は [07 運用マニュアル](07-operations.md) を参照してください。
