このガイドでは、専用画像ライブラリの準備、画像収集、定期画像・アルバム・音声送信タスクの設定手順を解説します。設定フィールドの詳細仕様は [デプロイ設定説明](../../config_example/README/ja.md)、各コマンドの権限と動作仕様は [09 コマンドリファレンス](09-commands.md) を参照してください。

## 専用画像ライブラリの準備

`config/dynamic/assets.json` で画像ライブラリのディレクトリパスを指定します：

```json
{
  "onlyPath": {
    "random_h_image_dir": "./h_image"
  }
}
```

- 絶対パス、または `./` や `../` で始まる相対パス（実行時データルート基準で解決）を使用します。データルートの設定については [07 運用マニュアル](07-operations.md) を参照してください。
- サービス実行アカウントに、対象ディレクトリの読み取り・書き込み・走査権限が付与されている必要があります。起動時にディレクトリが存在しない場合は自動作成されますが、既存ディレクトリ内のファイルは厳格に検証されます。
- 専用ライブラリには通常の画像ファイルのみを配置し、ファイル名は**画像バイナリの 64 桁小文字 16 進 SHA-256 ハッシュ値**に `.jpg`、`.jpeg`、`.png`、`.webp` のいずれかの拡張子を付与した形式である必要があります。サブディレクトリ、シンボリックリンク、規約に反するファイル名が存在する場合、システムは起動を拒否します。
- `/h_image add` コマンドを使用すると、画像ハッシュの計算とファイル名設定が自動実行されます（同一ハッシュの画像がすでに存在する場合は重複書き込みをスキップ）。画像の追加・削除を行った場合、以降の抽選処理には現在のディレクトリ内容が即座に反映されます。

パス指定の詳細ルールについては [assets.json](../../config_example/README/ja.md#assetsjson) を参照してください。

## 画像の収集と抽選

1. スーパー管理者が対象グループで `/init enable` を実行して Bot を初期化します。
2. `isCanAddHImage` 権限を持つユーザーが画像メッセージに返信して `/h_image add` を送信します。同一アルバム（メディアグループ）内の Bot が受信済みの画像もまとめて一括登録されます。
3. コマンドの実行結果（新規保存、既存重複、サイズ超過、取得失敗の各件数）を確認します。
4. グループ内で `/h_image` を送信すると、専用ライブラリから画像が 1 枚ランダムに抽選されて送信されます。送信される画像には常に Telegram のスポイラーマスクが付与され、ユーザーがタップした時点で表示されます。

対応画像形式、サイズ制限、コマンドのレート制限、およびメッセージ保持ルールについては [ランダム画像コマンド](09-commands.md#random-images) を参照してください。

## 定時画像の送信

定期タスクは `config/dynamic/cron.json` のタスク配列に定義し、ホットリロードに対応しています。以下は、指定したタイムゾーンの毎日昼 12 時に専用ライブラリから 1 枚を抽選して送信するタスクの定義例です：

```json
[
  {
    "name": "daily-library-image",
    "chat_id": [-1001234567890],
    "cron": "0 12 * * *",
    "time_zone": "Asia/Tokyo",
    "actions": [
      {
        "type": "send_image",
        "payload": {
          "rand_image": true,
          "content": "今日のランダム画像",
          "is_blurred": true
        }
      }
    ]
  }
]
```

サンプルのグループ ID を実際の送信先 ID に置き換え、スケジュールとキャプションを設定してください。タスク名はファイル内で一意である必要があり、`actions` 内の各アクションは宣言された順序で直列実行されます。

### 単画像・アルバム・ランダム画像

| 送信方式 | `send_image.payload` の画像指定方法 |
| --- | --- |
| 固定の単一画像 | `url: ["https://example.com/a.jpg"]`、または `path: ["./posters/a.jpg"]` |
| 固定のアルバム | `url` または `path` の配列に複数の画像ソースを指定 |
| 専用ライブラリからのランダム画像 | `rand_image: true`（`path` は省略） |
| 任意ディレクトリからのランダム画像 | `rand_image: true` とディレクトリパス文字列（例：`path: "./gallery"`） |

固定画像指定の `url` と `path` は排他関係にあり、1 枚のみの場合でも配列形式で指定します。複数画像を指定した場合はアルバム形式で送信されます。ランダムモードで `path` に任意ディレクトリを指定する場合、そのディレクトリ内の画像ファイル名には SHA-256 ハッシュ規則は要求されません。`is_blurred` は画像のスポイラーマスク適用を制御します（省略時は無効）。

### 時刻と送信先

- `cron` は標準の 5 フィールド式、または `@daily` 等のマクロ文字列を受け付けます。`time_zone` は IANA タイムゾーン名であり、省略時は `config/static/bot.json` の `time_zone` を継承します（Bot のデフォルトは `Asia/Tokyo`）。
- `rand_cron` には `"6h-12h"` のようなランダム時間間隔を指定できます。初回は `cron` の時刻に実行され、以降は各実行完了時に指定範囲から一様ランダムに次回実行時刻を再スケジュールします（分単位に切り上げ）。`just_once: true` を指定するとプロセス稼働中に 1 回のみ実行されます（`rand_cron` との同時指定は不可）。
- `chat_id` にはグループ ID の配列を指定できます。`["all"]` を指定すると初期化済みかつ送信権限を持つ全グループが対象となり、`["except", -1001234567890]` を指定するとその集合から特定のグループを除外できます。

## 定時音声とその他のアクション

定期音声送信を利用する場合は、あらかじめ `config/dynamic/agent.json` で `agent.tts` を有効化しておく必要があります。タスクの `actions` に以下のアクションを追加します：

```json
{
  "type": "send_voice",
  "payload": {
    "content": "おやすみ、また明日ね",
    "tone": "小声で"
  }
}
```

声色は `agent.tts.voice`、該当セリフの話し方・ニュアンスは任意の `tone` で指定します。同一タスク内で複数グループへ送信する場合、最初に合成された音声バイナリが安全に再利用されます。設定フィールドの仕様は [デプロイ設定説明](../../config_example/README/ja.md#agentjson) を参照してください。

タスクはこのほか、`send_message`、`send_file`、`send_web_digest` アクションにも対応しています。各アクションのパラメータ、必要な機能依存、文字数・件数の制限については [cron.json](../../config_example/README/ja.md#cronjson) を参照してください。

## 動作確認と実行中の変更

ライブラリのパス設定、サービス実行ユーザーのアクセス権限、グループの初期化状態および送信権限を確認した上で、画像収集と抽選の動作をテストしてください。定期タスク設定後は、タイムゾーンと次回予定時刻が正しく認識されているかをログで照合し、対象グループへの実際の送信を確認します。

`assets.json`、`cron.json`、`agent.json` はホットリロードに対応しています。タスク名に基づいて差分が照合され、変更のないタスクは既存のスケジュール状態を維持したまま稼働を継続します。起動バリデーション、ホットリロード、トピック指定、シャットダウン時の制約については [04 実行時の正式な不変条件](04-invariants.md)、データ移行手順については [07 運用マニュアル](07-operations.md) を参照してください。
